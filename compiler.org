* MIRICL compiler

MIRICL shares a Common Lisp frontend, target type rules, semantic optimizer and Wasm emitter
between the compiler running inside Wasm and host bootstrap tooling. Compact HIR also supplies
portable execution. Whole-program analysis retains reachable definitions and ordered
initialization effects, then emits portable or native bundles. This document describes current
mechanisms and interfaces; AGENTS.md supplies project-wide semantics and development rules.

** Interfaces and bootstrap

=compile-to-hir= lowers a lambda to semantic HIR; =compile-hir= produces an interpreted
function. =emit-hir-code= and =load-hir-code= expose checked retained code.
=emit-native-module= emits Wasm, literals and available debug metadata. =compile-native=
compiles and instantiates a lambda; =compile-native-hir= compiles retained HIR without
reconstructing source.

=compile-module-to-hir= accepts DEFUN forms and explicit entry points. =compile-native-module=
returns entry functions, bytes and HIR for a sealed module without changing global bindings.
Internal calls and FUNCTION references resolve lexical definitions; symbol designators retain
global lookup. Top-level evaluation and loading remain separate operations.

=miricl-compiler:*compile-evaluations*= controls REPL, EVAL and source LOAD boundaries. Native
policy compiles executable forms while processing top-level PROGN, EVAL-WHEN, definitions and
environment changes in order. Explicit =:interpreted= and DEBUG 3 use checked HIR execution.
NIL retains the source route for bootstrap and remaining lexical adapters. A guard prevents
compiler preparation from recursively compiling itself. Macro expansion and load-time
evaluation use target objects and dynamic bindings; failures propagate.

=miricl.wasm= links the precompiled compiler and starts =:ready= with origin =:image= .
=miricl-cold.wasm= retains the source compiler for interpretation and bootstrap.
=miricl-interpreter.wasm= supports scripting, portable code and native module loading without
the optimizing compiler. The source evaluator still serves bootstrap, NIL evaluation, source
closures and macro preparation. ASDF is loaded explicitly. The default browser image must
remain below 1 MiB raw; compressed download size is a separate concern.

The required bootstrap runs the compiler interpreted inside Wasm, compiles its kernels, and
compiles its definitions into a sealed native payload with shared literals and lexical
bindings. =ensure-compiler= coordinates requests, records failure or completion, and avoids
recursive bootstrap. Explicit =:interpreted= state preserves live source definitions.
Node/browser adapters instantiate emitted modules; WASI executes linked code and portable
FASLs but cannot load generated native code dynamically.

=miricl/cross= loads the same frontend, proofs and emitter on the host without a guest
bootstrap. =miricl-cross:compile-lambda= emits target bytes, literals and debug metadata;
=compile-module= also returns HIR. They neither install host definitions nor execute target
code. Target macro and LOAD-TIME-VALUE adapters are explicit; host expansion and EVAL are not
target semantics.

** Frontend, ownership and policy

The frontend assigns identities to lexical bindings, functions and control targets. FLET uses
the outer function environment; LABELS shares recursive bindings. Lambda normalization
preserves initialization order, declarations, optional/keyword processing, supplied-p
variables and argument checks. TYPE and THE attach scoped assertions; nested assertions
intersect and rebinding creates a new identity. FTYPE result types do not prove value counts.
When keyword parameter syntax reaches HIR lowering, an implicit or literal NIL initializer
without a supplied-p variable uses the keyword value lookup directly: absence already returns
NIL. Other initializers and supplied-p bindings retain the presence branch; final keyword
validation remains in order.

Untrusted source, macroexpansions, public HIR and serialized data are validated before
unchecked internals: structure, cycles, names, types, ownership, bounds, SSA dominance and
control edges. Literal graphs may share or cycle where permitted. Diagnostics identify
offending input with bounded summaries. Fresh compiler-owned HIR need not be revalidated
between passes, but changed edges require predecessor maintenance. Public consumers validate
on every entry; no certificate survives external mutation. Admitted declaration/type syntax is
snapshotted before callbacks can mutate shared source; literal identities and opaque type
arguments retain their intended sharing.

SAFETY and DEBUG retain lexical scope through deferred work and inlining. SAFETY 0 permits
declaration-based unchecked lowering without bypassing public validation. DEBUG 0 permits
eligible frame omission; DEBUG 2 retains native listings; DEBUG 3 selects interactive HIR.
SPEED, SPACE and COMPILATION-SPEED are retained separately from those contracts.
Whole-function policy summaries let local speed-oriented regions veto outlining. The compact
deployment policy is =(optimize (space 3) (speed 1))= ; STRIP and visibility remain explicit.

Inlining uses the caller's growth policy while preserving the callee's lexical bindings,
declarations, SAFETY and DEBUG. INLINE encourages bounded expansion; NOTINLINE vetoes it;
=:inline nil= disables automatic module inlining. The current estimator weights residual
calls, argument/result traffic, literals, indices and adapters, and prunes IF arms for narrow
literal-argument facts. It assumes out-of-line bodies remain and gives no sole-call removal
bonus. This is a weighted approximation, not exact complete-module costing. Original syntax,
nesting, total work and growth are bounded; opaque forms, macros and unsupported literals
decline estimation. It does not expand macros or execute user code. COMPILATION-SPEED controls
work independently of growth policy.

** Semantic HIR and proofs

HIR contains functions, blocks, SSA values, cells, captures and explicit transfers.
Instructions carry effects, scoped safety and available origins; multiple-value groups remain
distinct from primary values. Dynamic bindings, cleanup regions and nonlocal targets are
explicit. Retained bytecode keeps register identity, block metadata, literals, policy and
captures while omitting lowering-only source environments and producer structures.

Checked readers serve execution, disassembly and native reconstruction. Loading copies
executable containers once into private storage. Reconstruction checks externally determined
operand, parent, register and control contracts, then recomputes analysis. Private
=emit-hir-code-checked= and =%%hir-function-checked= avoid a serialization round trip only for
fresh owned containers; public emission and loading remain checked. The interpreter has fixed
small-call encodings, primary-call specialization and a bounded transient decoding cache
excluded from snapshots. Full-value and debugger calls retain their general protocols.

=hir-types.lisp= shares target relationships across inference, proof queries and lowering:
nominal families, unions/intersections, EQL/MEMBER, MOD, integer intervals, array rank and
element types. Opaque types remain unknown; proofs do not call host SUBTYPEP, expand arbitrary
DEFTYPE or execute SATISFIES. EQL identity and cyclic literal handling remain intact.
Depth/work limits yield no proof on exhaustion. Fresh inference propagates local values,
ranges, joins and closed-call arguments/returns while accounting for outside callers at
entries and escapes. HIR changes invalidate dependent facts.

Dominated truth tests and canonical predicates narrow values only across paths that establish
the premise. Aliases, writes, captured landings and unresolved entries prevent unsupported
propagation. Executed truth facts are available at every SAFETY level; unchecked declarations
retain their own restrictions. Arithmetic uses target intervals, contagion and bignum
promotion. Fresh CONS field observations and proper-list facts are temporary and invalidated
by mutation or unknown effects; LIST alone never proves a proper spine.

Semantic simplification forwards unaliased private cells, propagates constants and executable
edges, forwards empty blocks and preserves scoped assertions. Bounded branch-tail sharing
sinks matching suffixes of exclusive sibling arms in an acyclic graph, with identical dynamic
environments and corresponding SSA operands, literal/type identities and safety. It excludes
environment/capture changes and never moves work before an arm's prefix. The losing suffix
remains unreachable retained-HIR producer inventory: native reachability drops it, but
portable bytecode need not shrink.

** Native values, calls and control

Lisp values use WasmGC =eqref= ; raw numeric locals remain separate. Function objects retain
literals, captures, entry identity and available debug metadata. Public entries check a
function-and-argument packet. Eligible fixed-arity private workers use five reference
parameters: function context plus four operand slots. Checked adapters retain public arity
behavior and verify actual signatures before attachment; metadata never authorizes casting an
arbitrary funcref. This is not a variable-width or general wide-argument ABI.

Known exact calls reuse private argument-use masks to omit unused value roots and pass NIL in
unused physical slots. Producer effects, errors and evaluation order remain live. A bounded
closed-use audit can trim private returns to their primary value, excluding roots, exports,
escapes, captures, full-value uses, barriers and debugger/custom-worker contracts. Scalar
VALUES then roots only its first operand; discarded producers still execute when observable.
Analysis is emission-local, avoids recursive mask planning and invalidates affected caller
plans. Public and escaping entries retain complete values.

Result-count proofs independently distinguish zero values from one NIL. Executable VALUES,
copies, equal-count joins and proved closed calls can give exact counts; FTYPE cannot.
Eligible DEBUG 0 fixed-arity callees with a proved small result tuple and actual closed
consumers can use native multiple-result workers. Primary/full/tail/join consumers use
component locals; ordinary boundaries pack values. Failed signature-preserving rewriting falls
back. General primary/discard calls use =native-primary-call= and clear secondary state after
success; full consumers retain =native-call= .

Direct closed calls and frame omission require the applicable effect/debug contract. Dynamic
state, cleanup, captured exits and unknown calls retain ordinary dispatch. Global calls
resolve live user bindings at the required point; operand effects cannot be moved across
resolution. Standard primitive lowering retains argument, overflow and bounds checks without
guarding forbidden redefinition of COMMON-LISP functions. Method specializers alone are not
body type assertions: public METHOD-FUNCTION calls bypass generic applicability, and class/MOP
changes invalidate unguarded class assumptions.

Standard COMMON-LISP function names have their ANSI definitions; preserving their forbidden
redefinition is not an optimization contract. Existing compact checked plans can therefore
handle ordinary standard calls without an explicit INLINE declaration. NOTINLINE still
requires out-of-line calls. Same-name symbols in other packages, user functions, supplied
callbacks and extensible generic-function protocols retain their ordinary contracts.

Tail calls whose complete group flows to return use Wasm tail-call operations for supported
lexical and computed native callees, including FUNCALL/APPLY/MVC. Checks, global redefinition,
values, dynamic cleanup and scheduler polls remain. Unsupported calls use ordinary
application. Immutable captures can be direct; mutable captures share cells. Distinct function
objects and required capture identities survive body sharing and closure caching.

Integers are canonical i31 immediates, boxed signed-i64 values or larger sign/magnitude
integers; target FIXNUM spans signed i64. Proven scalar work can stay raw and share canonical
boxing. Overflow, large shifts, division traps and infinite two's-complement semantics retain
checks or general helpers. Private numeric cells require proofs for every write and no
capture/escape; reads keep SSA snapshots. Predicates can feed branches directly; bounded reuse
and loop motion require stable operands and nontrapping canonical operations. Typed
list/vector operations retain safety, definition and boundary contracts; LIST/LIST* preserve
fresh spines and operand order. APPLY/MVC binding rewrites check proper lists and arity before
unchecked reads.

At SAFETY 1, binary ordered comparisons can use signed-i64 instructions when fresh,
declaration-independent inference proves both operand ranges fit signed i64. A separate,
bounded representation check follows only copies and primary extraction to integer literals
or retained checked binary LOGAND calls. LOGAND validates its operands and canonicalizes
successful signed-i64 results. Extraction accepts both i31 and boxed i64 even for narrow
ranges; a range alone does not prove an i31 representation. Unknown facts or origins retain
the checked comparison helper. This comparison plan preserves producer evaluation and checks,
returns one ordinary Lisp value, and does not enable raw cells, branch fusion or loop motion.

Acyclic regions use forward structure; proved reducible natural loops use Wasm loops.
Irreducible, captured or exhausted cases retain dense dispatch. Transfers preserve block
arguments/environments and backedge scheduling. Native body passes perform liveness, local
coalescing, copy/constant folding, stackification and scope simplification without moving
effects or traps. Shared Lisp and Wasm kernels implement these passes. Module compaction pools
literals, merges equal bodies, removes unreachable code/imports and relocates all references.
Helper fusion and factory/table selection price encoded section costs. Runtime imports use
namespace =m= and omit the =native-= field prefix.

=native-forward-locals= forwards copies within straight-line instruction regions before
building flow and liveness facts. Adjacent local reads or tees followed by stores establish
equal values only for identical defaultable Wasm types. Per-local generations invalidate
copies when their source changes; control boundaries discard the region's facts. Calls
preserve activation-local equality. Stores remain for exception-aware liveness and
stackification to remove when safe, preserving landing-pad observations and initialization.
The native ABI supplies object-local types when explicit types are absent; unknown scalar
types decline forwarding. Dense tables and region epochs bound work to instructions plus
locals. The shared body entry applies the pass to guest emission, typed direct workers and
decoded whole-image bodies. Existing writers encode changed local indices and relocate call
offsets; whole-image optimization retains a body only when its final encoding shrinks.

=native-result-blocks= replaces eligible local-based joins with single-result Wasm blocks.
The void block's next instruction must read one known, single-byte defaultable local type.
Every branch targeting the block must be unconditional and immediately follow a store to
that local. Normal fallthrough must end in the same store or a direct terminating transfer.
The pass removes those stores, assigns the block its exact result type and changes the join
read to a tee, preserving later local observations. Other exits retain their effects and
order. Exception-bearing bodies, branch tables, typed conditional branches and unsupported
types decline this transformation. Original scope targets are resolved before edits, with
linear work and storage; no cached flow facts precede the rewrite. Subsequent passes treat
scope boundaries as stack barriers, and result blocks retain their signatures during scope
cleanup and final encoding.
Runtime worker adaptation maps object-valued control signatures to the same GC reference
ABI as its locals and parameters. Instruction extents distinguish single-byte result types
from signed-LEB type indices in encoding and disassembly.

=native-outline-code= shares repeated straight-line regions using exact normalized bytes
and Wasm types. Local renaming preserves aliases; reads before the first write become
inputs, and written locals used later become outputs. Regions neither consume inherited
stack operands nor cross control transfers. Unknown result types and bodies with exception
handlers decline outlining. Each site supplies its own local mapping, and selected sites
must not overlap. Encoded call, argument/result traffic, helper and section costs determine
whether sharing saves space under the function's policy.

Discovery checks every endpoint from 16 through 128 instructions, subject to minimum byte
size and stack shape. Local simplification can change region lengths, so endpoint selection
does not depend on a sparse length schedule. Per-function and global scan budgets, bounded
region length, and caps on groups, occurrences and helpers limit work and storage. Exhausted
budgets retain ordinary code; discovery order can limit the repetitions found.
Discovery extends local, input and write sets as each endpoint advances. Retained sites
own copies of their local mappings. A rolling fingerprint includes opcodes and nonlocal
immediate bytes, omitting original local indices and terminal local reads, including reads
appended for returned locals. Equal helpers share this fingerprint. Each fingerprint
caches a bounded set of representative groups: a streaming comparison checks complete
normalized helper bytes and parameter/result types before reusing their owned helper.
A miss constructs the ordinary normalized helper and uses the complete exact key, so
collisions or a full representative cache cannot hide matching groups. After group
admission fills, an absent fingerprint rejects a candidate before normalization. Bounded
integer arithmetic and an integer-keyed table keep the filter within the existing scan.

** Whole-program artifacts and runtime

COMPILE-FILE records =:miricl-ir= definitions, references, effects and reflection barriers.
=analyze-file= reconstructs definition IR without loading application code. Explicit
entries/retention root reachability; package exports alone do not. Calls, designators,
globals, classes, methods and load-time recipes add dependencies. Unknown initialization and
observable creation remain ordered roots; missing metadata or unbounded reflection
conservatively retains code. =shake-file= and =optimize-system= combine reachability with
graph compaction. =:strip nil= retains supplied definitions; it does not disable
representation compaction. =compile-native-bundle= emits initializers/closures, and =:load t=
executes each initializer before decoding the next dependent unit.

=fasl-format.lisp= writes indexed units in =miricl.fasl= custom sections with =MIRF= headers,
roots, object blocks and optional analysis/definition indexes. Unit-local references preserve
sharing/cycles. Checked directories, extents, counts, tags and references precede use.
Canonical lexical naming and graph pooling preserve quoted, uninterned, mutable and load-time
object identities. Native units share modules while keeping distinct literals/function
objects. Images retain reachable Lisp state, native bytes and captures, excluding transient
scheduler/decoder caches. Only matching current formats are supported. Bootstrap source
packing is separate, bounded and checked, and uses target symbol identities rather than
host-private names.

Bootstrap initialization bytes use a bounded LZ encoding with literal runs and overlapping
back references. A checked startup pass reconstructs the exact packed source bytes before
the ordinary source reader runs; its object freshness, offsets, contract facts and private
symbol identities are unchanged. The host encoder bounds its match search and the target
checks input/output extents, backward distances and the decoded size before use. Native
images also omit repeated imports/exports from generated package preambles after each exact
symbol's first installation, retaining generated record names and ordered registrations.
These mechanisms affect initialization storage and startup work, not optimization policy or
steady-state compiler queries. The compiler-free image retains its scripting interface.

Runtime CL kernels compile as sealed groups above representation/platform WAT. The kernel
linker checks dependencies, ownership, captures and signatures; public validation precedes
unchecked traversal. Fixed-callback proofs require immutable private ingress and reject
replacement, capture, escape or unknown provenance. List/sequence/stream/package/metadata
kernels share compiler sources; remaining representation adapters stay native until equivalent
lowering is suitable. Host tooling is not a shipped runtime dependency.

Effective-slot lookup uses the saved private metadata callback proof to call the checked
metadata service directly. This removes generic callback transport while retaining slot-list
validation before copying, live MOP slot-name reads, scheduling checkpoints and value handling.

Runtime multiple values use small slots/native tuples and checked owned overflow storage,
preserving full values across callbacks and unwind. Lexical binding views share mutable cells.
Generic dispatch retains live method, version, class and MOP guards and escaped next-method
context. HIR debugging shares visible cells with closures, checks declared writes and uses
ordinary nonlocal cleanup. Frame metadata is copied/validated; executable arrays are not
exposed. Native Wasm does not yet provide equivalent stepping instrumentation.

** ANSI standard-function contracts

=standard-contracts.lisp= defines target ANSI operation identities independently of host
FBOUNDP, host function types, package membership and runtime dispatch support. Recognition
requires the exact standardized symbol or function name. The inventory has 638 symbol
entries, including CALL-NEXT-METHOD and NEXT-METHOD-P as method-local operations rather than
fixed global entries. The two explicitly standardized SETF function names, (SETF CLASS-NAME)
and (SETF DOCUMENTATION), have separate descriptors. Standardized SETF places do not imply
standardized setter function names.

Each descriptor shares grouped, independently queried facts: argument arity and keywords,
argument/result types, successful result count, reads/writes, callbacks, signaling, allocation,
and sharing. All inventory entries and standardized SETF function names have arity and keyword
metadata; 590 symbol entries have successful result-count facts. Variable-value forwarding,
nonreturning control and method-sensitive operations can remain unknown. Missing properties
mean unknown; explicit NIL properties are known false. Successful-call facts do not validate
arguments, remove checks or establish purity. Generic signatures do not fix an effective
method, and callback effects remain independent of an operation's own mutation/allocation.

=standard-function-contract= accepts a symbol or bounded two-element SETF name and declines
malformed names. =standard-function-property= returns a fact and a known flag. Result type,
result count, predicate type and list-path queries expose the facts used by HIR and native
planning. Unknown type facts fall back to T; unknown count facts never mean one value.

*** HIR proofs and operation provenance

Inference, predicate premises and exact result-count analysis consume the shared descriptors.
NOTINLINE preserves semantic facts while prohibiting expansion. Integer predicate refinement
supports unbounded and bignum intervals; declaration-derived unchecked facts retain their
separate SAFETY restrictions. Native scalar result planning and eligible tail-result cleanup
also consume shared count facts, independently of effects and argument checks.

=hir-standard-operations= computes fresh semantic provenance through bounded primary-value
flow, copies, compatible joins and certified private-cell reads. It shares primary-flow and
ownership rules with executable-callee analysis and discards incomplete proofs on exhausted
work. A declared FUNCTION type, closure identity or a user symbol currently bound to a CL
function supplies no standard-operation proof. HIR mutation requires fresh maps. Computed
calls retain designator evaluation and out-of-line invocation; provenance alone permits
neither expansion nor removal of the function object from ordinary value consumers.

TYPEP and SUBTYPEP use bounded target relationships for recognized literal symbolic types
and a missing or literal NIL environment. Their calls remain checked and execute at the
original point. TYPEP can establish a successful true or false primary result; SUBTYPEP only
establishes true results where inclusion is proved. Opaque types, arbitrary DEFTYPE expansion
and SATISFIES callbacks supply no proof. No false or uncertain SUBTYPEP result is inferred.

*** Checked native linkage and list operations

Implementation-owned standard function and setter indexes record the actual entries installed
by STORE-FUNCTION. Builtin installation, replacement by compiled Lisp bodies and promotion to
generic functions use the same route. Snapshot roots retain the indexes. Signed operation
codes identify standard names without implying native availability; bootstrap fallback
manufactures entries only for genuinely available native builtins. Lisp definitions require
installation, and generic calls continue through live permitted methods and protocols.

Eligible exact one-value calls with zero through four operands use shared checked
=native-standard-call0= through =native-standard-call4= adapters. Other consumers and arities
retain the general checked path. Exact standard references can avoid public binding lookup;
ordinary user functions and arbitrary implementation setter names retain live resolution.
Checked linkage needs no operand-type proof, while unchecked workers still require one.
NOTINLINE calls remain out of line. Host runtime-kernel adapters retain their explicit linkage
and conservatively decline these mixed-signature plans.

Composite list reads use shared checked list paths, including under NOTINLINE, with NIL
behavior and each intermediate CAR/CDR check preserved. Standard list-place DEFSETF expanders
emit the prefix accessor or NTHCDR followed by RPLACA/RPLACD and return the stored value. These
place expansions are separate from references to arbitrary (SETF accessor) function names.
The compiler-free runtime receives generated expanders without the compiler's contract table.

MEMBER and ASSOC can use a shared checked search when static controls establish default EQL,
exact EQ/EQL tests or their TEST-NOT counterparts and no key callback. Unsupported or ambiguous
controls retain ordinary calls. Operand/control evaluation remains live. Search returns the
original matching tail or association entry, preserves first-match behavior and skips NIL
association entries; ingress, traversed structure and cycle checks protect the runtime boundary.
Scheduler checkpoints remain in shared call and traversal paths.

Compact plans also cover ATOM, LISTP, FUNCTIONP and IDENTITY; broader one-value operations can
use the checked standard-call adapters. Existing typed numeric/array plans retain their
specific proof gates. Backend dead-result/stability decisions require explicit effect facts
and accepted arity. LISTP means NIL-or-CONS, not a proper or acyclic spine. General arithmetic
retains arbitrary-precision and contagion behavior. Runtime sequence classification, default
character initialization and rational-interval arithmetic no longer carry captured standard
functions solely to guard forbidden CL redefinition.

*** Representation and remaining limits

Startup packing requires a checked decoding pass and temporary byte storage. Further
compression of =bootstrap-public-symbol-bytes= and =bootstrap-private-symbol-bytes= needs a
checked bridge for their immutable byte-array readers. Retained output-literal compression
would also affect =$emit-literal=, =$ascii-text-literal=, caches and snapshots. These candidates
must account for loader cost and compressed downloads as well as raw image storage;
initialization encoding does not change authoritative contract facts or query representations.

Inventory/signature coverage does not imply complete result/effect facts, specialized
lowering for every operation, or complete symbolic type reasoning.

** File compilation and owned CLOS metadata

*** File/native multiple-value integration

File preparation and lexical canonicalization retain resolved standard MULTIPLE-VALUE-BIND
syntax. The producer uses the outer environment; the body preserves lexical/special bindings,
declarations and captures. Prepared VALUES/APPLY and eligible small literal MEMBER calls use
semantic HIR lowering without consulting later macro definitions. Whole-program scanning
recognizes retained MVB bindings and masks outer function-value facts within their scope.
Boundary validation checks proper, legal, unique binding variables and valid bodies.

Immediate component consumers of proven exact local tuples of two through eight values use
component locals under a bounded planning budget. Captured/unknown joins, differing counts
and ordinary call producers retain the general path. Full-value boundaries reconstruct the
ordinary representation; public calling conventions and general call-result lists remain.
File/native lowering preserves zero/missing/extra values, operand effects, lexical macro and
symbol-macro scope, normalized defaults, mutable captures, special restoration and cleanup,
with or without block compilation. General optional/keyword argument cursors remain.

The file frontend's =%compile-lambda-parts= normalizes optional, keyword and auxiliary
parameters through =%normalize-lambda= before lowering executable HIR. Its keyword bindings
reuse a =%cell= result for presence and value. Native bundle compilation reconstructs retained
HIR through =initializer-hir-unit= rather than repeating source normalization; frontend
parameter changes therefore need not alter existing portable bundles.

*** Owned method keyword profiles

Method preparation captures implicit keyword symbols alongside the executable lambda list
while preserving the original METHOD-LAMBDA-LIST. The required canonical sixth
=%ENSURE-METHOD= argument supplies explicit executable keyword pairs to the checked private
allocator. Matching compiler/runtime artifacts use this format. Keyword identities survive
specializer evaluation that uninterns and reinterns an implicit keyword name.

Each owned standard method has a private WasmGC descriptor containing normalized keyword
identities and compact declaration shape, without initform graphs. Its lifetime follows the
method and it survives image save/restore. FUNCTION-KEYWORDS and initialization checking share
checked normalization. Returned keyword spines are fresh; FUNCTION-KEYWORDS preserves
declaration order and reports only explicit &ALLOW-OTHER-KEYS.

Every query invokes live METHOD-LAMBDA-LIST. Exact standard-reader, method/function/protocol,
storage, lambda-list and live token checks guard descriptor reuse. The final owned hit and
copy do not yield or call Lisp; borrowed matching may poll. No lock spans arbitrary Lisp
callbacks. Invalidating raw operations revoke proof directly. An epoch alone cannot justify
reuse across multi-step MOP/class/method mutation. Custom readers retain checked parsing that
observes same-spine and nested mutation. Borrowing preserves semantic identities while
revoking fast proof; borrowed NIL ownership is never promoted. A process-private unsaved token
requires restored descriptors to validate shape and symbol keys, with final live rereads,
before acquiring proof.

The initialization checker consumes its already-fresh method-key spine when building the
validity union. Both descriptor and fallback paths allocate this spine; descriptor cells and
custom-reader source cells never become union storage. Key order and identities are preserved.
The final key checker can retain or mutate the union without changing subsequent checks,
method metadata or independent FUNCTION-KEYWORDS results.

*** Owned generic metadata shape

A private generic metadata cache retains a checked finite/even property-spine fact. A
process-private unsaved token permits reuse only after validation and final rereads of metadata
identity, storage spine and ownership. Raw borrowing, storage replacement and class changes
revoke ownership directly. Value-cell updates and insertion of complete fresh pairs preserve
the shape fact. Restored cache arrays require validation before receiving the current token;
borrowed/NIL ownership is never promoted.

This fact caches no semantic property value, applicable-method set, custom MOP result or
permission-protocol outcome. Live calls and redefinition guards remain; specializer metadata
retains ordinary validation. On the valid owned path, guarded shape reuse and property-cell
traversal do not yield or call Lisp. Borrowed fallback remains checked live observation and
does not promise a snapshot of arbitrary concurrent user mutation.

*** Remaining compiler limits

Initialization still computes applicable-method unions, slot validity and requirements on
each request. Guarded whole initialization plans and reusable unions remain candidates;
mutable custom MOP readers preclude identity-only caching. Retained descriptors contribute
both code and data to shipped artifacts.

Argument/method-context transport, repeated keyword scans, interpreter callbacks and
continuation capture remain candidates. =hir-lambda= retains separate presence/value scans
