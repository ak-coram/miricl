* Whole-program compiler

Definition pruning removes unreachable FASL definitions and object records.
The native backend compiles retained initializers, function bodies and methods
into shared WASM modules. Interprocedural type inference, specialization of
arbitrary calls, removal of runtime primitives and compiled development support
for every defining form remain incomplete.

** HIR and bytecode design decisions

The default precompiled browser image has a design budget below 1 MiB
(1,048,576 raw bytes). Measure the uncompressed Wasm, gzip download and retained snapshot sizes
separately. Compression reduces transfer cost but does not relax the raw image
budget. Keep a compiler-free interpreter image for lightweight scripting.

The target is Common Lisp on Wasm. The HIR describes Common Lisp execution;
its compact bytecode executes the same semantic operations. Design the
lowering for WasmGC references, typed calls, structured control flow, exceptions
and Wasm multiple results. SBCL is a bootstrap host, not another compilation
target. Host execution of the compiler exists to bootstrap the Wasm runtime
and compiler. Development and application compilation use the compiler running
inside Wasm. Reuse the same compiler sources and passes for bootstrapping;
do not develop a separate host application-compilation product or a portable
backend framework.

Preserve Common Lisp distinctions explicitly: zero/one/multiple values and
primary-value contexts; lexical binding identity and shared mutable captures;
special bindings and dynamic extent; lexical and dynamic nonlocal exits and
UNWIND-PROTECT cleanup; function redefinition and extensible CLOS/MOP dispatch;
literal identity and sharing; numeric promotion and contagion; scoped type
assertions and Lisp conditions. Optimization and representation choices must
follow these contracts, including operand effects and evaluation order.

Use two storage forms for this semantic model. Compilation can use an editable
graph with explicit control/data flow. Retained functions use compact executable
bytecode, literal/capture references and only the metadata required by policy.
Packing changes storage, not the language semantics. Share instruction contracts
between construction, validation, interpretation, optimization and disassembly.
Wasm-specific lowering data can be temporary; it need not become another
representation retained in snapshots.

Snapshots should retain executable functions and required Lisp state, including
observable object and binding identities. Avoid retaining predecessor lists,
producer back-links, proof tables, lowering plans or full source forms through
each instruction. Rebuild derived compiler/runtime caches when needed. Measure
raw and compressed snapshot size alongside execution and compilation time.

*** Optimization and debugging policy

DEBUG 1 remains the default. It should provide useful function/frame identity
and compact source locations without the cost of full lexical inspection and
stepping. DEBUG 0 is the explicit policy for more aggressive stripping, and
final browser artifacts should be compiled under that policy. Higher DEBUG
levels can retain more variable and execution information for development.
SPEED, SPACE, COMPILATION-SPEED, SAFETY and DEBUG are scoped policy inputs;
debugging policy does not replace safety checks or alter Common Lisp semantics.

Build policy and interactive defaults are separate. Compiling shipped runtime,
compiler and application code at DEBUG 0 can produce a small browser image
whose newly compiled user code still defaults to DEBUG 1. Changing a global
declaration immediately before saving cannot retroactively strip emitted code.
Keep structural checks at public boundaries before SAFETY 0 internals.

Compile the shipped interpreter and compiler as sealed modules with block
compilation, SAFETY 0 and DEBUG 0. Sealing covers owned internal calls; public
entry checks and extensible Common Lisp/MOP hooks retain their contracts.
The compiler image already uses a sealed module; migrated CL runtime kernels
use sealed groups above the native substrate. Extend this policy as the
remaining handwritten interpreter is migrated, without changing user defaults.

The bootstrap endpoint is a jointly compiled sealed CL interpreter/compiler
module above the native representation/platform substrate. The current image
already links their Wasm into one physical module; that alone does not expose
separately lowered code to shared HIR analysis. Joint compilation can propagate
types and values across internal calls, inline small private helpers, specialize
internal representations/calling conventions and remove unused code. Preserve
checked public entries, interactive redefinition contracts and extensible Lisp/MOP
hooks. Migrate slices and measure code size/performance before broadening the
sealed boundary; a combined build must still meet the 1 MiB image budget.

Use the existing =strip= policy to select the retained endpoint surface.
=:strip nil= preserves all supplied endpoints; =:strip t= roots explicit entry
points and their reachable dependencies. Eventually apply the same policy to
the jointly compiled application, CL runtime and compiler, so unreachable
evaluation, compilation and loading facilities can disappear from fixed-purpose
images. Interactive images retain these facilities where reachable; they can
still share one compiled module. Compiler presence is not required merely
because it was used to build the application. This is a link/reachability goal:
current FASL stripping does not yet eliminate the native runtime substrate.
Stripped application startup and browser callbacks must enter compiled exports
directly: launching an application by reading/evaluating a Lisp string makes
the reader/evaluator reachable again. Export roots, callback tables, retained
function objects and ordered initialization effects participate in the same
reachability graph. Visibility does not override public redefinition or MOP
extension contracts; only owned internal calls may use the sealed boundary.

*** Source information and disassembly

Use compact origin identifiers with shared source-file/version and span tables.
Origins identify source occurrences, including repeated symbols and literals,
and should preserve macro-expansion and inlining provenance. Define one offset
convention at the reader/compiler boundary. Source text can be retained once
or supplied separately; a source location does not require retaining full forms
or a source-text copy per function. DEBUG 0 may omit this metadata.

Preserve binding identities and lexical scopes separately from physical storage.
Richer debug metadata can describe an optimized variable as a value, capture,
constant or unavailable, and relate inlined code to Lisp call contexts. It must
not require keeping every binding in a heap cell at the default policy.

DISASSEMBLE must support retained HIR/bytecode without requiring source forms
or the optimizing compiler. Show executable Lisp operations, labeled control
flow, value groups, literals, captures and available names/types. Add source
locations when retained; stripped functions must still have structural listings.
Native listings remain available when the image retains their instruction data.

These are design constraints for the interpreter migration, not a claim that
all debugging support is implemented. Packed HIR disassembly already exists.
Full source spans, expanded lexical/debug information and compiled stepping
still need implementation. The current DEBUG 3 source-evaluator fallback is
a temporary compatibility path, not the intended long-term debugging design.

** Deployment and compiler bootstrap

For bootstrapping, the host runs the HIR frontend, proof passes and Wasm emitter
directly. This is build tooling for producing the Wasm system, rather than a
second supported environment for application compilation.
Loading =miricl/cross= needs neither CFFI nor Wasmtime. The full =miricl= system
adds the Wasmtime host runner and the assembler still used for runtime WAT.
=miricl-cross:compile-lambda= returns Wasm bytes, literals and debug metadata;
=miricl-cross:compile-module= compiles a sealed DEFUN group with explicit entry
points and adds the HIR unit as its fourth value. These functions emit code
without instantiating a guest or installing function definitions. The initial
host interface accepts core CL forms; macros require an explicit target
=*macroexpand-hook*= adapter. It rejects host macro expansion by default,
because even standard SETF places can expand into host-private functions.
Keyword normalization and lexical macro environments still need host adapters.
=LOAD-TIME-VALUE= likewise requires an explicit =:load-time-evaluator= adapter;
cross-compilation never substitutes host EVAL for target evaluation.

For example, in a bootstrap SBCL REPL after loading =miricl/cross=:

#+begin_src lisp
(miricl-cross:compile-module
 '((defun checked-head (object) (declare (inline car)) (car object))
   (defun entry (object) (checked-head object)))
 :entry-points '(entry) :inline t)
#+end_src

This returns target code and metadata without defining either function in
SBCL. Reloading the emitter and repeating the call is the fast bootstrap
feedback loop; a full guest image build is a later validation step. The host
interface and explicit expansion adapters serve trusted bootstrap sources;
extending them into a general host application compiler is outside this scope.

Runtime migration starts with =runtime-kernel-library.lisp=. Its ordinary CL
property-cell lookup and checked helpers compile as a closed group; helper
inlining leaves one worker. The host linker proves that the worker needs no
closure, padded arguments or literals before changing its external-reference
view to the core's raw reference ABI. It resolves a small set of representation
primitives and links the worker directly as =$property-cell=. No Lisp function
object, startup compilation, additional module loader or kernel source ships
for that entry, including in the compiler-less image.


*** Kernel lowering and measurements

The identity-membership kernel uses the same pipeline with an i32 truth-result
ABI. The adapter normalizes Lisp truth values and cancels adjacent boolean
representation conversions on return. The compiler emits T through its scalar
boolean primitive without a function-owned literal, while retaining repeated
loop-literal caches. Backend reloads invalidate the host kernel cache using
the actual compiler function definitions, so REPL experiments do not silently
reuse code from an earlier emitter generation.

These initial kernels have fixed arity up to four and return one value. Their
raw callers own multiple-value state. The linker rejects unsupported
dependencies and captures; it does not
silently interpret them. Structural checks precede SAFETY 0 field access, and
malformed storage keeps the checked primitive error path. Ordinary compiled
Lisp loops retain their scheduler polls; only explicitly non-suspending kernels
omit them. The pairwise identity-list comparison uses =:interruptible t= and
retains the compiler's loop-backedge checkpoints. A circular comparison can
still yield and receive a nonlocal interrupt. Extend the interface incrementally,
measuring execution time and raw/compressed image size against each handwritten
implementation before replacing it.

Canonical inline operations also supply value-count facts. Single-valued
primitive results stay scalar through full-value returns and joins, avoiding
an allocated value-list packet. GETHASH retains its two-value path.

For DEBUG 0, a bounded analysis permits direct non-tail calls to known lexical
workers whose bodies require no dynamic cleanup or tail-frame replacement.
The initial rule accepts local state and canonical primitive operations;
unknown calls, dynamic bindings, captured exits and debugger entries keep the
ordinary call path. Public function objects retain their checked entries.
The analysis is rebuilt for every HIR emission. Its single-valued return facts
also remove redundant value-state resets; other primary-only callers retain
the reset after the call. Scheduler checkpoints remain. Both bytecode
optimizers receive complete internal signatures, including five-argument
workers, rather than assuming every internal call has two arguments.

The browser interpreter includes compact compiler source. It does not compile
anything at startup. The first compilation self-compiles the frontend and emitter
once; subsequent compilations reuse those native functions. A bootstrap failure
is reported and remembered rather than silently using an interpreted compiler.

For the REPL deliverable, Host Common Lisp assembles a temporary seed containing
the compiler's Lisp source. The build runs that seed in Node, compiles the compiler,
then uses the native frontend and emitter to compile its core functions again,
including the optimizer's graph traversal kernels.
The second compilation lowers the compiler definitions as one sealed module.
Its factory creates native entry functions sharing one literal graph and their
lexical function bindings. The generated Wasm functions are linked into the REPL runtime.
There is no separate compiler artifact or compiler fetch on startup. ASDF remains
an explicitly loaded, separate artifact.

REPL startup restores the precompiled functions and their shared literals. It does
not compile the compiler again. This image omits the corresponding compiler
source definitions where bootstrap initialization does not need them. Macro
expanders, other library helpers, and parts of the analysis layer still use the
shared evaluator. This is not yet a completely compiled Common Lisp library.

Compiler-mode ANSI runs require the frontend and backend to be native before
installing the RT compiler hook. Reports record that the self-compiled compiler
was initialized on first use. Browser regressions run offline using only the adapter and
interpreter, including mutable closures, multiple values, dynamic state and
JavaScript callbacks. Node and browser adapters can instantiate generated Wasm;
the WASI image runs the linked compiler and can emit code without an external
compiler file, but still lacks dynamic Wasm instantiation.

The import-free =miricl.wasm= artifact includes the bootstrapped
native compiler, with compiler state =:ready= and origin =:image= at startup.
It is the default browser/Node image. =miricl-cold.wasm= retains the source
compiler for bootstrap work; =miricl-interpreter.wasm= provides lightweight
scripting without the optimizing compiler.
It uses the same adapter and REPL bridge as =miricl-cold.wasm= and works in browsers
and Node without companion images or experimental flags. Native compilation
and the shared size passes run during the build rather than on first use.
The build caches this core and also embeds it in the REPL component, without
WASI or native stack-switching instructions, for Node. The Node command uses
that embedded core when =miricl-repl.wasm= is beside the interpreter; with only
the ordinary interpreter available, its host compiler self-compiles on first use.

=miricl-compiler:*compile-evaluations*= is a dynamically scoped evaluation
policy. It defaults to =nil= in =miricl-cold.wasm= and the WASI command, and =t=
in the default =miricl.wasm= image. The setting takes effect at public
evaluation boundaries: text REPL input, object requests, =eval=, and individual
source forms read by =load=. Recursive interpreter calls keep their lexical
environment rather than compiling each subexpression. Development REPL forms
use this same browser-local policy.
Compiled-file loading executes its existing FASL code without repeating the
source compilation pipeline.

Compiler evaluation shares the development path's top-level definition handling.
It processes =progn= and executing =eval-when= forms sequentially, installs native
=defun= bodies, compiles variable initializers, and interprets environment
definitions such as packages, macros and classes. Atomic forms and quoted
objects use the direct evaluator. A private dynamic guard prevents recursive
compilation inside compiler helpers, preserving the public policy's value for
macro expanders and load-time forms. Application code executes under the caller's
original dynamic bindings. Compilation and execution errors are
propagated, with no automatic retry that could repeat macro or application
effects. Bind the policy to =nil= around =eval= or =load= when interpretation
is desired, including forms without supported native lowering.

The default =debug= optimization quality is =1=. Level =0= is an explicit
opt-in reserved for more aggressive optimizations. Levels =0= and =1= retain
no disassembly data. Level =2= retains packed Wasm bytes shared by a module's
functions and closures; =disassemble= decodes and prints them inside the Lisp
runtime. Level =3= selects the interpreter at evaluation boundaries for
interactive debugging. Local =declare= forms override an inherited policy;
=declaim= sets the default for subsequent compilation.

Regressions follow the HyperSpec's [[https://www.lispworks.com/documentation/HyperSpec/Body/f_eval.htm][EVAL]] requirements for null lexical scope,
current dynamic bindings, all return values and literal identity, and [[https://www.lispworks.com/documentation/HyperSpec/Body/f_load.htm][LOAD]]'s
requirement to execute each top-level form before compiling the next one.

In development mode WebSocket messages carry terminal forms and output. The
Node and WASI bridges forward bytes and serve files without invoking a compiler.
The browser's evaluation policy decides whether each submitted form is compiled
or interpreted. Macro expansion, quoted objects, load-time values and execution
all remain in that browser heap. Ordinary expressions, =defun= bodies and
=defvar=/=defparameter= initializers use its native compiler when enabled;
environment definitions retain their evaluator handling. Compiler errors remain
visible. Game of Life's development page uses =miricl.wasm= so its
browser compiler is ready immediately. Synchronous and asynchronous evaluation
share this policy.

The target execution model uses native application code in development and
production. Development compilation preserves global indirection and
redefinition; production compilation performs whole-program analysis and
specialization. The evaluator remains necessary for dynamic evaluation and
uncompiled library support. Once those functions are compiled, the reader and
evaluator can become optional production extensions. Object storage, allocation,
numeric operations, closures and conditions remain part of the runtime.

** Integer representations

Generic Lisp value slots use WasmGC =eqref=. Integers have three canonical
representations, with automatic promotion and demotion according to value:

- Signed 31-bit integers, from =-2^30= through =2^30-1=, use =i31ref=.
  They occupy value slots directly and allocate no heap object.
- Other signed 64-bit integers use a scalar object subtype with an =i64=
  payload. It has no digit array and adds no fields to unrelated objects.
- Larger integers use immutable sign/magnitude arrays in base =2^15=.

Common Lisp =fixnum= covers both scalar representations, so its limits are
=-2^63= and =2^63-1=. =bignum= is the complementary integer range.
Arithmetic never silently wraps: the runtime checks scalar overflow and
falls back to the digit kernels. Signed-minimum negation and division use
unsigned magnitudes where necessary. Bit operations retain infinite
two's-complement semantics across all tiers.

The compiler emits small integer literals directly with =ref.i31=. For
single-value arithmetic and comparison calls, literal values and =the=
integer ranges can prove a safe native =i64= path. Immediate operands are
extracted directly; wider scalar operands use the runtime unbox entry.
Results are converted back to canonical Lisp values when they enter generic
value slots. The compiler guards the resolved built-in function so global
redefinition still works. When both operands fit signed =i64= but the result
may overflow, checked scalar entries promote through the runtime's ordinary
integer arithmetic. Narrower proven ranges retain entries without overflow
checks. General integer unboxing across control-flow
joins and function boundaries remains future work.

** Declarations and sealed modules

Local =type= declarations, their abbreviated forms, and =the= retain type facts
in HIR. Facts follow lexical binding identities, including captured and assigned
bindings, rather than variable names. Nested declarations intersect; a rebinding
starts a new scope. Bound declarations follow their bindings into subsequent
=let*= and lambda-list initializers; free declarations start at the body.
Local =ftype= declarations describe call result types,
including multiple values, without changing the number of values returned.
Recognized bounded integer facts select scalar arithmetic. Full-width =fixnum=
sums, differences and products use overflow checks and retain bignum promotion.

=infer-hir-types= computes fresh primary-value facts for each emission. It
propagates constant intervals through lexical assignments and control-flow
joins, including captured nonlocal exits. It infers local function return
types and propagates argument types when all callers are known and the
function has not escaped. Captured cells and debugger-visible bindings stay
conservative. Unknown global calls retain unknown results. Multiple-value
cardinality remains a separate analysis, so inferred primary types cannot
discard extra values or turn zero values into one value.
Explicit native exports are open to outside callers. The emitter passes its
=:entries= to inference; =infer-hir-types= accepts the same option for clients
requesting facts with an explicit export set.

Explicitly inlined canonical built-ins provide further result facts: =cons=
returns a cons, simple-vector =length= returns a bounded nonnegative integer,
and bit operations propagate integer ranges. A nonnegative =logand= mask or
negative =logior= operand bounds successful results even when the other
operand can be a bignum. Operand evaluation and type errors remain observable.
At safety 0, proven list and simple-vector operands permit direct inlined
accesses. Inlined =cons= and general =length= use direct runtime entries;
general length retains proper-sequence checks and fill-pointer semantics.
Canonical inlined predicates and hash-table accesses also bypass function
lookup and argument-list dispatch. Hash reads use a compact primary-value
entry when other values are unobserved, and retain the presence flag otherwise.
Hash defaults and setter operands keep their evaluation order and table checks.

The analysis uses dependencies and a worklist. Lowering requests only facts
needed by its current numeric and vector optimizations; clients may also
request facts for an entire HIR unit. Inferred facts never overwrite source
assertions, and emitting a rewritten HIR graph recomputes them.

=hir-optimize.lisp= simplifies semantic HIR before compact-code or native
lowering. Private lexical cell reads use reaching SSA definitions within a
block and across visited predecessors. A bounded join query forwards an
identical reaching value only when every predecessor supplies it. Immutable
private bindings use their initializer directly, without per-edge state.
An observed private-cell load supplies a reaching value until the next write,
so repeated reads can share its SSA value even at an unresolved loop header.
Ambiguous joins and loop-carried assignments retain their cells. Capture and
alias exclusions come from actual graph uses, and
debug levels 2 and 3 keep their bindings. Forwarded reads retain their own
scoped type assertions on =:copy= values. Nullable-type narrowing follows
these SSA copies without changing the type of their shared source.

Conditional constant propagation jointly solves primary-value constants and
executable edges. Only constants and structural value operations participate;
it executes no application functions or host type expanders. Literal identity
and the full value group selected by a branch remain intact. Its dense tables
are indexed by validated HIR identities, and an exhausted work budget applies
none of that query's provisional facts. Empty-block forwarding preserves
dynamic environments and has a total traversal budget. Changed edges refresh
predecessors before inference. Explicit =optimize-hir= calls validate structure,
internal operand representations and dominance before entering the passes.
Acyclic functions use one topological pass, with the same dense CFG ordering
solver used by native lowering; cyclic functions retain the bounded fixed point.

Native reachability omits unreachable blocks in cyclic functions as well as
acyclic ones, retaining captured nonlocal landing targets. Dead canonical
inlined predicates, identity operations and proven nontrapping scalar operations
can disappear; their operand effects remain in order. Fresh cons allocation can
be removed when unobserved, but is not treated as an interchangeable or movable
value. General sequence checks, hash operations and potentially trapping vector
accesses retain their ordinary effect requirements.

The shared target type rules interpret =and= intersections, =or= unions,
=member= and =eql= types, =mod=, and inclusive/exclusive integer intervals.
Unbounded endpoints can become finite when intersected. Union intervals are
conservative hulls; gaps are not treated as possible evidence for a rewrite.
Integer joins reuse an existing interval when it already covers the union;
intersections reuse an operand when its bounds already describe the result.
This reduces allocation without treating holes in =member= or union types as
continuous intervals.
Unknown type specifiers remain opaque and do not run host =deftype= expanders
or =satisfies= predicates. Literal arguments of =member= and =eql= retain
=eql= identity, including cyclic objects. Structural type comparisons memoize
shared DAGs, and recursive proof queries have depth and total-work limits.
An exhausted query provides no additional proof.

Truth tests and canonical explicitly inlined =null=/=not= calls narrow
nullable types in dominated acyclic regions. A join is included only after
every predecessor has established the premise. Outside predecessors and
unresolved loop backedges stop propagation. Dense block IDs index the small
predecessor-count and traversal tables. The premises are dependencies
of the affected reads, so they participate in the same worklist as module
argument and return summaries. Actual cell uses must establish no writes,
aliasing or capture; client-provided binding flags alone are insufficient.
Debug-visible functions and possible captured nonlocal entries are excluded.
A linear visit budget bounds region analysis, keeping the analysis small
and predictable.
Canonical predicate results can pass through read-only temporaries, including
those introduced by =cond= expansion. Writes or aliases that expose the cell
prevent using the temporary as a predicate certificate.

The same integer rules prove binary identities for addition, subtraction,
multiplication, =logand=, =logior=, =logxor= and =ash=. A singleton integer
operand can make the result equal to an existing operand, including unbounded
bignums. Inference retains that operand's type; safety-0 canonical =inline=
calls can return its value directly. Both operands must be proven integers,
and their expressions still run in order. Unknown, floating-point and complex
operands retain ordinary arithmetic and its type conversions or errors.

Canonical explicitly inlined =zerop=, =minusp=, =plusp=, =evenp= and =oddp=
use direct Wasm tests at safety 0 when their operand fits signed =i64=.
Integer intervals can prove a sign/zero result, and singleton integers can
prove parity even outside the scalar range. Parity proofs query the target
integer kernel without invoking a redefined application predicate. Unknown,
floating-point and complex operands retain ordinary calls and their errors.
The compiler kernels explicitly inline these predicates alongside arithmetic;
application policy remains unchanged.

Canonical =eq=/=eql= calls share the integer interval rules. Disjoint ranges
prove either comparison false; equal singleton ranges prove =eql= true,
including bignums. Equal numeric values never prove =eq= identity. These facts
flow through private module arguments and returns, while exported or escaping
helpers retain the possibilities supplied by outside callers. Safety-0 inline
lowering can replace the comparison with its proven boolean, preserving both
operand evaluations. Opaque types and overlapping intervals retain the ordinary
comparison.

Native branches can consume an adjacent canonical scalar predicate directly,
without first boxing its boolean result. Only a single-use suffix of copies,
truth normalization and scalar primary-value extraction participates. Operand
evaluation remains in place; another instruction stops the scan. Shared or
otherwise observed predicate results retain ordinary Lisp booleans, and
debug-visible functions keep their original lowering.

Reducible natural loops can use Wasm =loop= regions with direct branches instead
of a program-counter dispatcher. Bounded dominance checks identify backedges;
backward-numbered exits alone are not loop evidence. Reverse predecessor
closure derives each body. Disjoint and nested loops must form a proper forest;
crossing regions are rejected. Topological checks validate every collapsed body
and the surrounding graph before selecting the layout. Region count, storage,
nesting and proof work are bounded. Captured landing entries, debug-visible
functions, irreducible cycles and exhausted budgets retain dispatch. Transfers preserve block
arguments and dynamic scopes, and backedges retain scheduling polls.
Structured lowering is used whenever these proofs succeed.

Within one basic block, canonical nontrapping predicates can reuse a previous
result for identical SSA operands. Transparent scalar copies share the original
value during liveness and local allocation, rather than requiring extra
temporary stores. Literal keys compare identity and never traverse quoted data,
including cycles. Mutable heap contents, general calls, full value groups,
captured nonlocal entries and debug-visible functions retain ordinary handling.
Cheap tag checks are rematerialized across effectful operations to limit live
ranges. The query has a work budget and applies only complete equivalences.


The first LICM pass hoists canonical, nonallocating predicates whose operands
are established by definitions dominating the loop header or are literal values.
It tries containing loops from inside outward, retaining a proven inner
placement when an outer placement cannot be justified. A bounded, cached
dominance query permits outer-iteration snapshots to move outside inner loops.
It follows bounded
scalar copy chains without borrowing type assertions scoped only to the loop
body. Integer comparisons, sign/zero tests and parity require independently
proven signed-64 widths at the new location; literal proofs use actual values.
Integer addition, subtraction, multiplication, increment/decrement and bitwise
operations can move when the shared interval rules also prove that the result
fits the target's immediate signed-31 representation. This excludes numeric
allocation as well as overflow; wider results retain ordinary placement.
General calls, mutable heap reads, allocating operations and full value groups
remain in place. Prefixes execute before the selected loop, while all operand
effects keep their original positions. Cached results have dedicated locals.
Immutable capture-slot addresses can also move before a loop at DEBUG below 2.
Their mutable cell contents stay inside the loop; reading an exit-token address
does not activate the exit. Scoped assertions on the capture result prevent
speculation. This does not prefetch captures used only in unrelated branches.
Single-use branch suffixes cache raw Wasm =i32= conditions; observed Lisp values
retain their boxed representation. Work is bounded and entry
blocks that are themselves loop headers cannot supply a prefix's operands.
Bootstrap and subsequent native compilation use the same optimization pipeline.
There are no pass-enable settings.

At safety 0, these facts can select direct =1+=/=1-= operations, prove
arithmetic fits =i64= even when operand widths alone are insufficient, and
fold known =consp=, =simple-vector-p=, =null= and =not= results. Operand effects
and multiple-value behavior are preserved. Arithmetic outside the proven
scalar domain retains promotion. Type structure is checked at source and
public HIR boundaries before inference enters unchecked kernels.
Scalar arithmetic entries accept proven =i64= operands and share the actual
built-in function guard. Redefined functions use the ordinary Lisp call path.
The overflow checks are shared in the runtime rather than copied at each call
site. =scripts/benchmark-typed-arithmetic.mjs OUTPUT BEFORE AFTER= compares
these paths with narrow and unrestricted operand controls, recording emitted
bytes, imports and CPU timings. This microbenchmark supplements the larger
application measurements; it does not establish an application-level speedup.
=scripts/benchmark-typed-vectors.mjs OUTPUT BEFORE AFTER= compares reads,
writes and copies with untyped, typed and explicitly inlined controls. It
alternates the images across five measured rounds and records kernel sizes,
imports, compilation time and execution CPU time.

=safety= defaults to =1=, retaining the existing checked access and promoting
arithmetic paths. =(declare (optimize (safety 0)))= enables trusted operations
where type declarations provide the required facts. Incorrect declarations
have undefined consequences. Typed list reads omit generic argument dispatch;
typed simple-vector accesses omit Lisp bounds diagnostics. WasmGC still checks
the lowered 32-bit indices; invalid Lisp indices have undefined consequences.
Calls retain global function redefinition unless explicitly
inlined; =notinline= prevents these substitutions.
Declaring arithmetic operands =fixnum= alone still allows bignum results;
omitting overflow checks also requires a result assertion that fits =i64=.

Safety policy follows lexical scope, including deferred frontend work,
initializers, closures and inline function definitions. =proclaim=/=declaim=
can change the default for subsequent compilations. =compiler-source-policy=
adds =safety 0= and =debug 0= to compiler kernels during first-use bootstrap and image
generation, without changing the application default. The compiler's source
declares internal record/table representations, byte and index ranges, and
lexical environments. Liveness bitmaps remain arbitrary nonnegative integers.

An explicit =inline= declaration permits snapshotting the current builtin
=svref=, =aref= or =row-major-aref= implementation, including their =setf=
functions, when safety is zero and the
operands prove a simple vector and a bounded integer index. These calls use a
direct Wasm entry without function lookup or dynamic function/argument dispatch.
The compiler verifies the canonical builtin at emission time; a replacement
already installed before compilation is never mistaken for that builtin.
Subsequent redefinition does not change the inlined call. Unused function
references disappear, while first-class references and ordinary calls keep
their dynamic behavior. Writes mutate the original vector, preserve operand
evaluation order, and return exactly the stored primary value. Compiler kernels
explicitly inline these vector accesses. General and specialized arrays keep
their ordinary access paths.

=compile-module-to-hir= accepts a list of =defun= forms and explicit
=:entry-points=. =compile-native-module= lowers and instantiates that group,
returning an alist of entry names and native functions, the module bytes, and HIR.
Neither operation installs global function bindings. Within the group, ordinary
calls and =function= references resolve to the group's lexical definitions;
symbol function designators retain their ordinary global lookup semantics.
Compile-time top-level effects and file loading remain outside this API.

#+begin_src lisp
(miricl-compiler:compile-native-module
  '((defun successor (x) (+ x 1))
    (defun answer (x) (successor x)))
  :entry-points '(answer))

Small fixed-arity local functions can be inlined with a bounded expansion budget.
Arguments are evaluated in the caller, then bodies are lowered in their original
lexical environment. Local =inline= and =notinline= declarations control the
choice; =:inline nil= disables automatic small-function inlining for a module.
Unused local function objects and bodies are omitted, including helpers whose
calls were all inlined. Escaped functions and recursive calls retain native
entries. The compiler image disables automatic inlining because its bootstrap
entry functions remain exposed and shared code avoids duplicating their bodies.
Identical native bodies can share code while keeping distinct literal/capture
contexts. Known lexical tail callees use direct Wasm =return_call= instructions,
with the existing debugger dispatch fallback and scheduling checkpoints.

** IEEE bit conversion

The guest extensions =miricl:float-bits= and =miricl:bits-float= reinterpret
IEEE representations directly in Wasm. =float-bits= accepts a float and returns
its unsigned 32- or 64-bit integer representation. =bits-float= accepts an
unsigned integer of that width and a float prototype selecting the format.
Out-of-range bits and non-float prototypes signal a type error. Short floats
share the single format, and long floats share the double format.

Explicit bit construction accepts infinities and NaNs. Promoting a single
float into its internal double-width slot can quiet a signaling NaN under
Wasm's NaN rules. Ordinary arithmetic retains its invalid-result checks;
rational conversion and decomposition reject nonfinite values. The printer
uses descriptive unreadable representations, and signals =print-not-readable=
when readable output is requested. Compiled files reconstruct nonfinite
literals through the existing load-time-value record, so they need neither
a new FASL format nor JavaScript conversion helpers.

** Native tail calls

The compiler recognizes calls whose complete multiple-value result flows
directly to the function return, including through effect-free joins and local
block returns. It emits stable Wasm =return_call= instructions to a runtime
dispatcher, which resolves the actual callee and uses =return_call_ref= to enter
native code. Both the caller and dispatcher frames disappear. This supports
self recursion, mutual recursion, closures and computed function designators;
it does not depend on recognizing a particular function name. Tail calls through
the built-in =APPLY= and =FUNCALL= dispatchers and =MULTIPLE-VALUE-CALL= use the
same path. Global function redefinition and argument evaluation order remain
observable.

Tail-call lowering is conservative when a call has active local dynamic bindings
or captured nonlocal block targets, or a debug optimization level of at least 2.
Bindings and captured targets confined to other branches do not inhibit a call;
uncaptured lexical blocks have no runtime dynamic extent.
Those calls retain the ordinary runtime path, as do interpreted and other
non-native callees. Outer cleanup and handler scopes remain active around a
tail-recursive native computation. Multiple values, dynamic binding restoration,
nonlocal exits, argument checks and thread checkpoints retain their normal
semantics. Connecting a debugger alone does not disable optimized tail calls;
debug-enabled callees preserve their interactive entry path.

** Reachability and effects

Entry points and explicitly retained definitions establish the public surface
of a fixed production program. A package's export list is not a set of roots.
Applications must expose additional dynamically selected APIs explicitly.

Calls, function values, symbol designators, globals and class/type references
form dependency edges. A reachable generic function retains all its supplied
methods. Methods extending runtime generics wait for their supplied class
specializers to become reachable; native and unknown specializers stay
conservative. Method registration retains its generic binding without
automatically retaining sibling methods. Generated constructors, predicates,
copiers, readers and writers retain their owning defining form, including
inherited structure accessors across compilation units. Unused ordinary
class/structure registrations may be removed. Shared-slot initialization,
custom metaclasses, EQL-specializer evaluation and observable metaclass
initialization stay live. Registration and other unknown initialization
effects remain ordered roots. Dead bindings with literal initializers may be
removed; initializers with unknown effects remain live.
Unbounded type designators and class/method introspection preserve the input.
Unknown callbacks and escaped type factories preserve supplied classes until
interprocedural value flow can bound their inputs. These are conservative
semantic guards, not library-specific reachability rules.
Definitions containing load-time values or MAKE-LOAD-FORM objects also remain
roots until their load-time evaluation effects can be proved removable.

An unbounded reflective operation or a compilation unit without metadata
retains the supplied program. This is intentionally conservative. The report
records root and dependency reasons rather than silently assuming reflective
operations cannot observe removed definitions.

Local function bindings are tracked lexically: FLET definitions see the outer
function environment, LABELS definitions see their recursive bindings, and
uncalled local bodies do not create global dependencies or reflection barriers.
Taking a local function as a value retains its body. Constant IF tests select
only the executable branch for dependency analysis. Compilation policy names
in INLINE/NOTINLINE proclamations do not retain executable definitions.
Load-time object creation dependencies are recorded separately from call edges.

The FASL backend traces record edges from retained roots and coalesces repeated
immutable code and similar file constants within each compilation unit, as
permitted by [[https://www.lispworks.com/documentation/HyperSpec/Body/03_bdd.htm][CLHS 3.2.4.4]]. Uninterned symbols, cyclic subgraphs,
MAKE-LOAD-FORM objects and LOAD-TIME-VALUE creation records retain their identities.
Mutable load-time values are never merged. Repeated top-level roots remain
ordered evaluations even when their code is shared. Production output omits
analysis metadata; the definition directory is optional. Pass =:strip nil= to
=shake-file= or =optimize-system= (=--no-strip= on the terminal command) to
retain every definition while compacting its representation. All graphs are
compacted before replacing the output.

The =compile-native-bundle= backend emits native initializers and closures.
With =:load t=, it executes each initializer as native code before decoding the
next one, so package, function, class, and load-time dependencies are available
in their original order. Computed object literals retain native creation
entries for their =LOAD-TIME-VALUE= recipes. This supports objects containing
closures without requiring =MAKE-LOAD-FORM= methods for those computed values.
The loader creates them when first needed and shares the resulting objects.

** Executable HIR and interpreter migration

=compile-hir= lowers a lambda with the compiler frontend and executes compact
HIR in a Wasm register loop. =emit-hir-code= and =load-hir-code= expose the code
boundary. Each function has one byte string containing its basic-block table
and instructions. Register operands use ULEB128; instruction headers retain
safety policy, and function references retain INLINE/NOTINLINE policy. Literal
identity and creation order still belong to the existing FASL object graph.
Type annotations are Common Lisp type declarations; optimization facts are
recomputed when =compile-native-hir= reconstructs semantic HIR for native output.

Register IDs carry identity rather than definition order. Native local
allocation resolves environment-alias dependencies explicitly and compresses
their paths.

The Wasm block and instruction readers are shared by validation, interpreter
execution, native compilation, and HIR disassembly. The host Lisp fallbacks are
excluded from both browser images. Readers reject truncated data, excessive
counts, invalid opcodes and operands; the loader privately copies executable
containers. Before native lowering, checks also establish internal operand
representations and SSA dominance, including lexical exit landing edges.

The execution model resolves lexical accesses before execution, avoids
boxes for immutable private bindings, specializes small calls, and
constructs capture vectors directly. The Wasm loop reads operands
directly from decoded register indices rather than copying every
instruction's inputs into another object array. Primary calls with up
to four arguments reuse the native backend's checked call
helpers. These inspect actual function objects, preserving global
function redefinition. Multiple-value consumers retain the full call
path, and debugger evaluation keeps the general application path and
its frame handling.

Primary calls with zero through four arguments have fixed-count wire opcodes.
Their operand counts follow from the opcode, saving the stored count and
runtime arity selection. All variants share the =:call-primary= operation for
validation, debugging and native reconstruction. Larger calls retain the
variable-count encoding and general application path.

At debug levels below 2, compact-code lowering removes lexical target
allocation when captures and actual uses prove that the target cannot escape.
It aliases the scope's environment to its parent and lowers local exits to
checked jumps. Those jumps still validate multiple-value packets and restore
the destination block's environment. Captured exits retain their dynamic-extent
checks; higher debug levels retain the original scope objects.

The shared decoder has a checked fast path for one-byte operands. It returns
instruction metadata as Wasm multiple results and stores only indexed operands
in a reusable native scratch array. Metadata stays in Wasm locals; operand
gathering finishes before callbacks or thread safepoints, so nested calls and
threads can share the buffer without allocating one per HIR invocation.
Public readers retain their Lisp
scratch-vector API, including unsigned destination IDs and zeroed unused
attributes. Their caller-buffer bounds are checked independently of the reused
native buffer. Fixed input counts come from the opcode table; variable counts
are checked against the operation's limits.

Revisited small blocks can execute from a bounded transient decoded cache.
It uses the same checked reader, then stores packed instruction metadata and
operand IDs without caching Lisp values. Byte offsets remain available for
debugging. The cache is excluded from snapshots; larger or cold blocks retain
ordinary checked decoding.

Fixed-arity native calls with up to four arguments use exact-length WasmGC
reference arrays for their argument packets. These contain only argument
references, avoiding Lisp object headers and unused slots. The existing
native-call ABI and arity checks are retained; interpreter and general calls
continue to use their normal argument lists.

The shared runtime count conversion accepts nonnegative immediate integers
directly. Other values retain the checked magnitude/saturation path, including
boxed integers, bignums and negative/type-error cases. This avoids repeated
limb extraction for HIR indices without weakening boundary validation.

Global function lookup reads the current binding on each call. Once SYMBOLP
has established a symbol representation, it reads that symbol's ID directly,
avoiding a repeated tag test. SETF names and unbound functions retain the
FDEFINITION path, so redefinition and undefined-function conditions remain
observable.

Finished HIR releases lowering-only source and inlining environments. Its
parameter metadata contains names rather than executable default forms.
Stored code has local/capture names and declared types, with no defining lambda
source copy. =DISASSEMBLE= prints the selected function's labeled blocks,
registers, bindings, captures, instructions and types without requiring a
compiler in the receiving image. Closures share code and mutable lexical cells
through ordinary runtime objects, also supported by application snapshots.

The ordinary interpreter and file compiler use compact HIR. Debug level 3
currently keeps the existing evaluator path while HIR stepping, lexical scopes
and frame evaluation are implemented. This is a temporary compatibility path;
retained code and richer debugging support should follow the design constraints
above, with size and performance validation at each migration step.

** Indexed FASL format

Each =miricl.fasl= custom section contains one independent unit, identified by
the =MIRF= magic, followed by flags, record/chunk counts, a block size and a
directory. There is one current format, with no version field or compatibility
reader.
All directory fields are little-endian unsigned 32-bit integers. Directory
entries contain kind, key, payload-relative offset and byte length:

- kind 1: ordered top-level root IDs;
- kind 2: optional analysis metadata, skipped by normal LOAD;
- kind 3: object record blocks, keyed by block index (256 records per block);
- kind 4: optional definition names, initialization classification and root IDs.

Production output omits kind 4 by default. Pass =:index-definitions t= to
=write-program=, =shake-file= or =optimize-system= to keep this index. The block
directory and ordered roots remain present in either form.

Chunks encode integers with ULEB128 and strings with UTF-8, using a private
string pool per chunk. Lists and vectors have explicit lengths. Object records
use a dedicated record-block tag (10), a base record ID and a record count.
Strings use minimal UTF-8 lengths, whole-string references, or a previously
decoded string's prefix plus a UTF-8 suffix. Prefix lengths count characters,
preserving Unicode boundaries; each chunk has its own dictionary.
Byte-valued strings use tag 11 and one byte per character when that is smaller
than the complete prefix-reference/UTF-8-suffix encoding, including its length
and reference fields. This avoids expanding a large binary suffix merely to
save a short prefix. They join the same
dictionary, so later strings can reference them or reuse their prefixes.
Header flag bit 2 advertises this encoding; older readers reject the unit
before executing its initializers. Readers still accept earlier UTF-8 units.
Nil, number, character, string and symbol records have compact opcodes.
Symbol opcode 12 reuses the preceding symbol's package and namespace within
the block. Cons opcodes 6--8 carry the first cell's instruction flags and a
list-run length, followed by CAR references and the final CDR. Opcodes 9--11
omit a final CDR of record ID zero. Internal CDRs point to consecutive record
IDs; subsequent cells have zero flags. Opcodes 16--201 pack lengths 1--5,
flags and per-CAR absolute/delta choices into one byte; 202--234 pack lengths
6--16 and flags. These packets also end at record ID zero. Other explicit
edges choose a tagged absolute ID or zigzag delta, whichever is shorter.
Other records use opcode 0 followed by the generic description grammar. Object edges
remain unit-local record IDs, preserving sharing and cycles across blocks.
Native Wasm codecs handle the traversal loops; host Common Lisp uses a portable
implementation of the same grammar. Compiler and runtime artifacts are rebuilt
together when this format changes.

The native emitter imports only the runtime operations used by the module,
keeps uncaptured variables in Wasm locals and omits closure declarations when
there are no closures. Acyclic control flow uses nested Wasm blocks and forward
branches without a dispatcher; cyclic graphs use BR_TABLE dispatch for backward
edges while forward edges branch directly to the existing block labels or fall
through to the next block. Only entry, backward and captured-exit targets occupy
the dense dispatch table. Backward edges restore dynamic state before scheduling
polls; forward transfers use the destination's environment restore. Immutable
captures store values directly; captured mutable variables retain shared heap
cells. Global calls remain indirect so redefinition continues to work in development.
Native entries with a known fixed arity of at most four accept a private argument
packet in place of an allocated argument list. Public APPLY and variadic entries
retain their ordinary list behavior. Required parameters and arity checks read
packet fields directly; function objects retain their literals and captures.
Installing an anonymous native initializer closure as a global function retains
its name for =function-lambda-expression= and backtraces; aliases preserve that
original name.
Closures capturing only bindings already retained by their parent are cached
per parent function and literal environment, including captureless closures.
Closures over parameters, local bindings or targets of the current invocation
retain their own capture vectors. The last private capture-vector slot stores
this bounded cache; captured mutable cells continue to be shared.
Native checkpoints use a short counter for clock sampling and an 8 ms elapsed
time slice for preemption. The normal path avoids context snapshots and value
register updates; pending interrupts still enter the delivery path immediately.
Explicit yields and blocking waits always switch, independent of that budget.
Method invocation also packs its private next-method context into one object
instead of allocating a list. The dynamic binding and closures retain that
context through nested calls, nonlocal exits and escaped CALL-NEXT-METHOD closures.
APPLY of a literal lambda with up to four required parameters is inlined into
checked local bindings. Proper-list and arity checks run before binding; dynamic
declarations, captured mutable variables, multiple values and lexical exits keep
their normal semantics.
The same transformation handles a sole =&rest= parameter, sharing APPLY's
final list as permitted by the standard; optional/keyword processing inside
the normalized lambda body retains its existing validation. Other APPLY calls
retain the ordinary calling path.
The same inlining handles a literal =MULTIPLE-VALUE-CALL= target with one
value-producing form. It exposes the complete value group as the checked
argument list, preserving zero values, arity errors, dynamic bindings and
escaped captures. This also removes temporary function calls introduced by
normalized =SETF= and =MULTIPLE-VALUE-BIND= expansions.

=just benchmark-game-of-life= builds and optimizes the FSet 2 application,

File compilation canonicalizes lexical variable and local function bindings

Special bindings, lexical scopes, local function blocks and quoted objects
retain their semantics; this pass does not depend on application packages or

Production totals exclude the REPL. The application build uses the native
backend after pruning. Each compilation unit shares one module with separate
initializer entries and literal vectors. Object reconstruction and initialization
remain ordered, so packages, classes and cyclic constants retain their load
semantics. The initial native local layout reuses temporary locals within basic
blocks and keeps bindings, block arguments, dynamic scopes and values crossing
blocks separate. A subsequent Wasm pass computes CFG liveness and coalesces
noninterfering object locals across branches and loops. Parameters and the
integer dispatch local retain their ABI positions. Handler-bearing functions
conservatively retain distinct locals, with every call observing their local
state. This also prevents stackification from hiding stores needed by a handler.
Single-use stores/loads become operand-stack values without moving or duplicating
their computations. Dead tees disappear, dead stores become drops, and local
copies are folded after coloring. Local numbers favor frequently accessed
values; unused declarations disappear. Runtime imports are ordered by use count,
and sufficiently large modules similarly order shared function bodies after
deduplication, updating exports and closure references with their new indices.
The linked runtime counts ordinary calls, tail calls and function references,
including those from the native compiler, when assigning one-byte function
indices. Snapshot accessors follow the runtime helpers so they do not displace
those helpers from the short-index range. Compiler-free images omit the native
optimizer kernels while retaining input validation and compiled-code loading.
The bootstrap symbol-reference bank is selected from the forms actually shipped
in each image, including the native compiler's literal graph after its source
definitions have been removed.
Spare bootstrap tags are selected by their encoded savings from frequent list
prefixes and integer constants. Integers use zero-length entries in the existing
prefix table, with a ZigZag payload; other entries identify a list's head symbol,
namespace and length. The dictionary is private to each built image.
Bootstrap strings use references to earlier encoded contents and reconstruct
fresh strings. Each character-data, LOOP and CLOS stream owns its dictionary;
reference indices are checked before use. LOOP and CLOS forms are decoded
before evaluation so initialization cannot overwrite bytes still needed by a
reference. Record macros register their host inline metadata when cached
definitions load, and library expansion uses a local temporary-name counter.
Fresh and cached host loads consequently produce identical source images.
Inputs at their last use can share a local with the instruction's result.
The emitter omits untargeted block labels before local optimization and relies
on Wasm's zero initialization for an initially zero dispatcher local. Literal
caches exclude immediate integers and instructions removed by inlining or
liveness. Small integer literals can share an already imported integer-boxing
helper rather than repeat their conversion instructions.
CASE tests branch directly to the selected clause: a truth-only membership
consumer needs no matching-tail literal or value-producing join. Actual MEMBER
calls still return and share the appropriate tail of their literal list.
INLINE EQL uses identity comparison when either operand is a literal outside
NUMBER and CHARACTER. The ordinary numeric/character comparison and canonical
definition checks remain in place.
An unobserved canonical EQL result consumed by a branch uses an i32 predicate,
without constructing a Lisp boolean. Observed results retain their ordinary
Lisp value and multiple-value behavior.
Adjacent stores and loads become =local.tee=, and copies of a local to itself
are omitted. Single-use constants are loaded at their use; NIL needs no local
even when used repeatedly. Literal lookup preserves the original object's
identity and does not repeat its construction. Newly emitted native units also
pool and lay out their literal graphs before serialization.
Equal native bodies share code while retaining distinct function objects,
literal vectors and captures. The browser instantiates each shared module once;
loading an application does not bootstrap its Lisp compiler.

The portable pass is implemented in =wasm-optimizer.lisp= and self-compiles with
the other compiler kernels. Initial bootstrap and the shipped compiler image
use the same HIR, loop-motion and size passes. The image builder recompiles the
compiler as a sealed module for shared literals and lexical function bindings;
that packaging step does not select a different optimization policy.
No external Wasm optimizer is required.

=wasm-module-optimizer.lisp= is a host-only adapter to these same passes. It
decodes core-module types, function signatures and exact instruction stack
effects, preserves type/function indices, and remaps local and label names.
Interpreter generation runs it before stripping names and packaging components;
this covers the ordinary interpreter, WASI core and embedded Node compiler
core. Unsupported instruction sets retain the original function body. Typed
non-defaultable reference locals retain their initialization stores and distinct
slots to respect Wasm's structural definite-initialization validation. GC types
and externally shared signatures are never rewritten.

Further size passes are shared by native output and distribution cores:

- Integer precomputation uses exact i32 wraparound, signed/unsigned comparisons
  and masked shifts. Constant reference-null tests and conditions also fold.
  Division, floating-point conversions and trapping GC operations remain intact.
- Vacuum removes discarded constants, local/global reads and nontrapping unary
  operations, turns =local.tee; drop= into =local.set=, and removes self-copies of
  globals. Operand evaluation order is preserved.
- Constant conditional arms become a block containing the chosen arm.
  Straight-line unreachable suffixes disappear. Untargeted void blocks and
  loops disappear with their branch depths rewritten; exception and reference
  cast branch scopes are retained conservatively.
- Local coloring can reuse dead parameter slots of matching types. Parameters
  keep their original positions, and locals live at entry retain their implicit
  zero/NIL initialization rather than inheriting argument values.
- Native module reachability starts at every exported initializer or entry.
  Unreachable functions and imports disappear after code cleanup. Calls,
  =ref.func=, exports and declarative element entries follow the new indices.
  This module format has no externally mutable function tables or hidden roots.

The optional ASDF artifact uses =shake-file :strip nil= to pool its complete
object graph and remove compiler indexes. Its portable compiled forms work in
both Node and stable WASI hosts; a native ASDF experiment could not be loaded
by the WASI host, which cannot dynamically instantiate new Wasm modules.
The compact artifact measures about 302 KB raw / 126 KB Brotli, compared with
1276 KB / 225 KB before compaction. ASDF appears in the generated image size
HTML and JSON reports, including its section accounting.

The liveness solver reuses basic-block topology across passes, summarizes each
block once per pass, and solves forward-only graphs in one reverse sweep.
Cyclic graphs iterate summaries to a fixed point. Local allocation stores
directed interference masks and checks both directions against each color's
members and outgoing neighbors, avoiding expansion into individual reverse
edges. Handler-bearing functions skip interference construction and receive
distinct colors directly. These speed improvements preserve the allocation
order and emitted application bytes.

Byte emission appends encoded ranges with =replace= instead of dispatching once
per byte. The decoder handles single-byte instruction operands directly, and
stackification indexes candidate stack cells by instruction position. Its stack
of real-operand barriers preserves operand order without scanning sibling stores.
For native emission, a direct Wasm stackification kernel uses unboxed candidate,
epoch, operand and barrier arrays. General core modules retain the Lisp pass
for arbitrary instruction stack effects and non-defaultable reference locals.
Liveness likewise has a direct Wasm kernel over the shared records, retaining
arbitrary-width integer bitmaps, cyclic CFG iteration and exceptional-call
conservatism. The Lisp implementations remain available for host compilation
and differential regression checks.
The instruction simplifier also runs directly in Wasm, using unboxed instruction
indices for its active stack and scope matches. Its Lisp reference checks both
the surviving instructions and mutations to removed records. Constant arithmetic,
discarded producers and constant branches preserve the same traps and effects;
scope cleanup still uses the shared Lisp pass.
Public HIR validation indexes opcode shapes in a shared =eq= table while keeping
graph-specific ownership and cycle tables fresh for every validation. Empty list
spines return immediately; nonempty spines retain structural and cycle checks.
Native two-argument =vector-push= and =vector-push-extend= calls append directly
when capacity is available; growth uses the ordinary array implementation.
Native modules emit each function once against the complete ABI. The final
reachability pass compacts and reorders imports while relocating the existing
bodies. Positional HIR record macros create vectors directly in hot frontend
paths, preserving the ordinary keyword constructors and record interfaces.
Scope removal uses an indexed control stack and prefix counts of removed
labels. Resolving and relocating a branch is constant time in its nesting
depth, including branches to the implicit function label.
Acyclic entries created for immediate evaluation omit local/stack size passes:
each instruction executes at most once. Persistent function bodies, escaped
child closures and cyclic entries retain their ordinary optimization policy.
The runtime decodes native bytecode into the same optimizer records directly
in Wasm, with the portable Lisp reader retained for host compilation and
unsupported encodings. Stackification indexes candidates by local number and
invalidates them with epochs at control boundaries, avoiding hash lookups and
table clearing in its instruction loop.

For ACL2, =scripts/benchmark-acl2-startup.mjs IMAGE CORE REPORT= measures loading
and world initialization without proof tests. Add =--profile= for attributed
CPU samples or =--save-image= to record the initialized image size.
The portable and native ACL2 build scripts also accept
=MIRICL_ACL2_PROFILE_DIRECTORY= and an optional phase regular expression in
=MIRICL_ACL2_PROFILE_PHASE=; profiling stays disabled by default.
With a prepared FriCAS bootstrap and optimized core,
=node scripts/benchmark-fricas-compiler.mjs BEFORE.wasm AFTER.wasm= measures
compilation, compaction, loading and native emission for three algebra libraries.
Both benchmarks alternate image order over three rounds and require identical
application bytes. The FriCAS benchmark also records runtime image sizes in raw,
gzip and Brotli formats; it excludes startup and bypasses the algebra cache.

Loading currently decodes all object blocks eagerly. The directory permits
independent lookup and later decoding, but deferred bodies, external archives
and dependency fetching are not implemented yet. Initializers remain ordered
roots; an eventual deferred body must reuse already initialized literal cells.
