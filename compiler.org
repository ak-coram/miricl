* MIRICL compiler

The host and Wasm compilers share a Common Lisp frontend, target type rules,
semantic optimizer and Wasm emitter. Source becomes semantic HIR, which can
be retained for portable execution or lowered to Wasm. File and system
compilation add a definition graph for ordered initialization and
whole-program reachability.

** Interfaces and bootstrap

| Interface | Result |
|-----------+--------|
| =compile-to-hir= | Semantic HIR for a lambda |
| =compile-hir= | A function executed by the HIR interpreter |
| =emit-hir-code= / =load-hir-code= | Checked retained code and its executable form |
| =emit-native-module= | Wasm with literals and available debug metadata |
| =compile-native= / =compile-native-hir= | An instantiated lambda from source or retained HIR |
| =compile-module-to-hir= / =compile-native-module= | Sealed HIR or instantiated entry functions, bytes and HIR |
| =miricl-cross:compile-lambda= / =miricl-cross:compile-module= | The host versions emit target artifacts without running target code |

Module compilation takes DEFUN forms and supports explicit entry points.
Internal calls and FUNCTION references use lexical definitions; symbol
designators retain global lookup. Instantiating a sealed module does not
install its definitions globally. The host tooling provides explicit
adapters for target macro expansion and LOAD-TIME-VALUE.

=miricl-compiler:*compile-evaluations*= controls REPL, EVAL and source LOAD.
Native evaluation compiles executable forms and processes top-level PROGN,
EVAL-WHEN, definitions and environment changes in order. =:interpreted= and
DEBUG 3 use checked HIR execution. NIL selects source evaluation, including
bootstrap and lexical adapters. Expansion and load-time evaluation use
target objects and dynamic bindings.

When native evaluation is enabled, =CL:COMPILE= can compile an explicit
lambda expression directly using an already ready compiler and the host
module loader. =:interpreted=, NIL, DEBUG 3 and recursive preparation use
minimal compilation. Existing function objects follow the minimal path,
which preserves their lexical environments and previously compiled code.

=miricl.wasm= starts with a precompiled compiler in =:ready= state and
=:image= origin. =miricl-cold.wasm= carries the source compiler.
=miricl-interpreter.wasm= runs source and portable code and can load existing
native modules without the optimizing compiler. ASDF is loaded separately.
Node and browser adapters instantiate generated modules. WASI supports linked
code and portable FASLs, with dynamic native-code loading unavailable.

Bootstrap starts the compiler interpreted inside Wasm. It compiles its
kernels and definitions to obtain a disposable native compiler, using a
speed-oriented policy for that stage. After restoring the original policy,
the native compiler emits a sealed shipping payload from the saved source
corpus. =*native-compiler-seeds*= identifies its native definitions.
The main startup factory builds closures in the sealed group and pairs
them with a literal vector of names in entry order. It returns fresh
binding pairs for installation. The bootstrap checks their order and
identity before recording their symbol namespaces. For passive startup
graphs, the host uses these entries to omit source for private file
preparation and FASL writing helpers that run after installation.
=*native-compiler-cold-functions*= identifies opt-in planning, portable pass
and infrequently used helpers retained in the interpreted library. Shared
Wasm kernels serve common passes in the shipped compiler. =ensure-compiler=
coordinates preparation and records failure or completion without reentering
bootstrap. Explicit interpreted mode keeps live source definitions usable.

** Frontend, ownership and policy

The frontend gives lexical bindings, functions and control targets distinct
identities. FLET uses the outer function environment and LABELS establishes
recursive bindings. Lambda normalization preserves initializer order,
declarations, arity, optional and keyword defaults, and supplied-p semantics.
TYPE and THE assertions are scoped. Intersecting assertions refine the same
binding; rebinding makes a new one. File preparation retains resolved
MULTIPLE-VALUE-BIND, VALUES, APPLY and other supported forms with their
lexical semantics. The native bundle backend can reconstruct HIR without
repeating source normalization.

Source, macroexpansion results, public HIR and serialized inputs have checked
boundaries. The relevant validators check form shape, finite spines, names,
types, bounds, ownership, SSA dominance and control edges before unchecked
internals use them. Diagnostics identify the offending input with bounded
summaries. Literal graphs may retain sharing and cycles. Admitted declaration
syntax is snapshotted before callbacks can mutate it and opaque type arguments
retain their identities. Compiler-owned HIR remains private between passes.
Mutation invalidates dependent analysis, including predecessor information
when edges change. Public consumers revalidate caller-owned inputs. Public
type inference checks operand representations and SSA dominance before
using definitions. HIR shape validation requires unique instruction
placement and block parameters, and identifies the incoming dynamic
environment as the function-produced value.

The optional =miricl-environment= service supports custom free declarations,
including =DEFINE-DECLARATION=, =DECLARATION-INFORMATION= and
=AUGMENT-ENVIRONMENT= with =:DECLARE=. Its checked handlers receive the
incoming environment. Their opaque values live in lexical metadata and
supply no optimization proof. Source preparation and direct HIR preserve
their respective observation points. Binding-specific handler categories and
other augmentation keywords are unsupported. Debugger scope packets omit
this metadata.

The default compilation policy is =(optimize (space 2) (speed 1))=.
Image packaging uses a SPACE 3 default when compiling the shipped compiler
and runtime kernels and outlining runtime code without policy metadata.
Explicit source policies and recorded Wasm policies still apply.
SPEED and SPACE guide growth and code sharing. COMPILATION-SPEED separately
bounds analysis. Visibility and STRIP are explicit controls. SAFETY and
DEBUG retain lexical scope, including across deferred work and inlining.
SAFETY 0 allows declaration-based unchecked lowering after public validation.
DEBUG 0 permits eligible frame omission, DEBUG 1 permits bounded inlining
and owned tail-frame reuse, DEBUG 2 retains native listings, and DEBUG 3
selects interactive HIR. The separately audited native leaf case below can
also omit its own frame at DEBUG 1.

** Whole-program optimization and file artifacts

COMPILE-FILE records =:miricl-ir= definitions, references, effects and
reflection barriers. =analyze-file= reconstructs definition IR without
loading the application. Explicit entries and retention directives root
reachability. Dependency edges include calls, designators, globals,
classes, methods and load-time recipes. Observable initialization stays
ordered. Missing metadata, unknown effects or unbounded reflection retain
the affected definitions. =shake-file= and =optimize-system= combine
reachability with graph compaction. =:strip nil= retains supplied
definitions and still permits representation compaction.

=fasl-format.lisp= writes indexed units in =miricl.fasl= custom sections.
Validation checks unit directories, extents, counts, object tags and
references. The unit-local graph preserves shared, cyclic, quoted,
uninterned and mutable objects, and namespaces preserve private symbol
identities. Native units can share modules and keep separate literals and
function objects. =compile-native-bundle= emits initializer closures.
Loading executes each initializer before decoding the next dependent unit.
Reconstruction keeps each unit's dynamic context through nested LOAD and
preserves initialization order and traversal checkpoints.

Bootstrap source and symbol-name tables use a separate bounded LZ
encoding. The host searches a bounded hash chain for nearby one-byte
distances and longer or farther two-byte matches. It minimizes the packed
size across the resulting match prefixes and literal runs, including
their token headers. A greedy parse handles streams beyond the size or
work budget. Before each
copy the decoder checks input and output extents and backward distances.
It requires the exact output length before handing reconstructed bytes to
the readers. Native package
preambles also avoid repeating identical registrations while preserving
their installation order. These are startup-storage transformations.
Compiler, runtime, serialized artifacts and packed sources use matching
current formats.

** HIR analysis and semantic optimization

*** HIR and retained execution

HIR represents blocks, SSA values, shared cells, captures and explicit
control transfers. Effects, scoped safety and available source origins
travel with instructions. Dynamic bindings, cleanups and nonlocal targets
are explicit. Multiple-value groups have a distinct representation from
primary values.

Retained code preserves registers, block metadata, literals, policy and
captures. Public loading copies executable containers into private storage.
Disassembly and native reconstruction use checked readers. Reconstruction
reestablishes analyses from validated operands, registers and control
contracts. Fresh owned containers can use private checked-construction
entries directly. The HIR interpreter specializes common small calls and
primary results, with general full-value and debugger paths. Its bounded
decode cache is transient. Capture validation preserves the shared cells
used by closures and debugger writes.

*** Type, effect and provenance proofs

The same target type relations serve inference, proof queries and lowering.
They cover nominal families, union and intersection, EQL/MEMBER, MOD,
integer intervals, array ranks and element types. Opaque types and exhausted
queries supply no proof. Reasoning never executes SATISFIES, expands
arbitrary DEFTYPE definitions or substitutes host type relationships for
target rules.

Local SSA flow, bounded range joins and widening, and eligible closed call
arguments and returns propagate facts. External callers, captures and
escaped functions restrict those facts. Dominated truth tests, standard
predicates and integer comparisons refine the observations tested. Both
SSA operands of a comparison can matter to a refinement. Reachability must
be complete before excluding an edge. Bounded private-use analyses can also
prove a quoted-list cursor or a traversal counter invariant. Mutation,
aliasing, captures, unresolved calls and unknown effects can invalidate
such facts. A LIST fact permits NIL or CONS and gives no proper-spine proof.
Checked inference invokes the interpreted literal-counter proof worker
only when it has a certified cursor length.

A bounded audit of private integer cells joins the successful result ranges
of the initializer and every store. A literal-initialized counter that
advances by one toward a literal limit also bounds the number of updates to
private accumulators. The recurrence proof checks the entry and backedge,
excludes exceptional entries, and uses the continuing counter range only
for reads that precede its store. Unknown ranges and exhausted analyses
leave the ordinary arithmetic and overflow promotion available.

Source-owned sealed modules can propagate executable argument facts through
audited lexical function cells. The audit identifies the actual initializer
and every read, and requires used snapshots to feed known calls directly.
An exposed closure, a used write result or an unresolved use keeps the
function's arguments open. Explicit entries also keep open ingress. The
audit belongs to one emission and excludes debugger-visible modules.

=standard-contracts.lisp= records exact ANSI operation identities and
separate facts about arity, keywords, types, successful value counts,
effects, callbacks, signaling, allocation and sharing. Method-local
operations have no fixed global entry, and a standardized SETF place
supplies no authority to treat its setter name as standardized.
=standard-function-contract= admits symbols and bounded SETF function
names. =standard-function-property= distinguishes a known false fact from
an unknown property. The available facts vary by operation.

Operation provenance follows live primary values through eligible copies,
joins and private cells. A declaration, a same-named symbol, or a user
binding currently holding a standard function gives no such provenance.
Accepted arity and executable operand facts can prove individual
properties, such as non-signaling LIST access or an integer comparison.
They establish neither arbitrary effect freedom nor permission to omit a
poll. TYPEP and SUBTYPEP use the same bounded symbolic type rules for
recognized literal arguments while retaining the original checked
operation. Successful-return type, value count and primary-value demand
remain distinct.

*** Simplification and inlining

Semantic simplification forwards private cells, propagates constants,
prunes proved unreachable edges, and forwards empty blocks. Bounded
branch-tail sharing moves a matching suffix to a common successor when
operands, effects and dynamic environments agree. Operand evaluation,
scoped safety and observable transfers stay in order.

Inlining uses the caller's growth policy and preserves the callee's lexical
bindings, declarations, SAFETY and DEBUG. INLINE encourages bounded
expansion, NOTINLINE requires out-of-line calls, and =:inline nil= disables
automatic module inlining. The bounded estimator uses residual calls,
arguments, result traffic, literals and adapters, and can discard an IF arm
under narrow literal facts. It approximates encoded growth while assuming
the original out-of-line body remains. It declines opaque forms and does
not expand macros or run user code. Whole-function policy summaries also
let a local speed-oriented region veto Wasm outlining.

** Native lowering and specialization

*** Values, calls and control

Lisp values use WasmGC references. Native function objects retain their
entry identity, literals, captures and available debug metadata. Public
entry points validate function and argument representations. Eligible
private fixed workers have a context and four reference operand slots.
Checked adapters verify actual signatures before attachment. Operand-use
masks do not exempt ignored operands from public validation.

Known private calls can avoid transporting unused values, while keeping
observable producers and their order. A closed-use audit can also limit a
callee to primary-value return. Escaping and public entries retain complete
groups. Exact-count proofs distinguish zero values from one NIL and can
select component locals or typed Wasm results for supported tuples. The
ordinary adapters preserve zero, secondary and overflow values across
calls, callbacks, and cleanup. FTYPE and primary demand supply no exact
count proof. Tuple transport and frame omission require independent
admission.

Native result analysis can keep supported four- through eight-value
returns in component locals. These returns publish an exact count,
fixed secondary slots and a private immutable array of secondary values.
One-argument calls and eligible no-prefix APPLY calls can capture and
project present components without allocating a Lisp spine. The adapters
retain argument validation, entry checkpoints and frame cleanup. Raw
projection and materialization check the transport shape, value count and
read operands. General groups and list consumers use Lisp spines.
Scheduling preserves the ambient result group across callbacks. Lisp list
consumers materialize the group before it can enter a saved image.
Bootstrap emission and host-linked runtime workers use the ordinary
result convention.

In a source-owned sealed module, a retained non-tail DEBUG 0 call can use a
private fixed worker that returns i64 directly to an existing scalar
arithmetic consumer. A bounded function scan skips instruction analysis
when no DEBUG 0 caller with a frame plan has SPEED greater than SPACE. When
a caller qualifies, the work budget covers the full unit. The compiler
requires an exact one-value proof, a nonescaping frameless leaf, a checked
range proof for its arithmetic result and a result with only scalar uses.
The ordinary object entry remains available for closure attachment. Both
operation-entry polling and one-value cleanup remain in place. The emitter
bounds duplication and checks the relocated worker's final call edges and
entry references before publishing the module. A failed plan restarts
emission with the ordinary calling convention.

Shared fixed-call adapters cover up to four operands. A matching worker can
avoid the input packet while the shared executor still owns frames, dynamic
state, result admission and cleanup. General application retains the
binder for optional, rest and keyword arguments, debugger entry and arity
errors. Keyword binding can share lookup and default handling when the
missing-argument result supplies the default and no supplied-p value is
needed. Native packet ingress checks representation, bounds and elements,
and snapshots mutable storage before defaults or callbacks. Individual
positional reads from list and vector transports also validate the
physical representation of the selected value. Ordinary REST
bindings materialize a fresh list where required. Proven private
observations may use the packet.

Native, HIR and source references share a checked resolver for live
function bindings, including bounded SETF names. Each mode retains its
original lookup point and saved function objects retain identity after
rebinding. The native fused lookup checks the owner, literal pool and index
before resolving the selected name. Native standard references also have
a dense installed-entry table indexed by exact ANSI identities. Signed
linkage codes are validated against the inventory before indexing. The
source evaluator's fixed-call selector reads its cached canonical builtin
after checking operation and arity eligibility. Permitted generic
extensions, callbacks and live protocols still use their required dispatch;
NOTINLINE keeps the call out of line.

Supported tail calls, including eligible FUNCALL, APPLY and
MULTIPLE-VALUE-CALL, use Wasm tail operations with their checks, complete
result groups, polling and unwind behavior. The bounded list APPLY path
validates its argument spine and elements before private reads. The
shared-list route observes the current spine after the callee entry
checkpoint. For a short proper list and an ordinary boxed native entry,
it copies the arguments into indexed storage so optional, rest and keyword
binding can reuse that observation. Other targets retain the ordinary list
protocol. Native binder ingress still snapshots mutable packets before
defaults or callbacks.

*** Frame omission and executable validation

DEBUG 0 frame omission uses separate bounded certificates for scalar and
tuple paths. Eligible leaves can seed closed forwarding chains, with
known callee identity and matching fixed arity, while recursive and unknown
dependencies keep their ordinary entries. The caller's retained frames
and restoration owners remain independent of the callee's certificate.
Ordinary calls retain the frames and cleanup needed by signaling,
debugging, polling and dynamic-state changes.

The native source evaluator can bind apparent recursion in a DEFUN to its
own fixed worker under the Common Lisp recursive-call consistency rule.
Source lowering records the identity of directly resolved call operands
after macro and lexical resolution. Emission checks their surviving uses
against the originating calls. Local and proclaimed NOTINLINE preserve live
lookup. A scoped body proof admits matching-arity non-tail calls with
primary demand and retained frames. Eligible tail calls replace the current
frame and forward the full value group. The executing function supplies
the recursive context, and both routes retain the entry checkpoint and
transfer cleanup. A bounded exact-one query closes the recursive result
equation over admitted calls only, with a concrete producer and agreement
between the original and revised call plans. After relocation and outlining,
the emitter audits the checked entry adapter, worker descriptor, incoming
references and recursive frame protocols. Failed admission or audit retries
ordinary emission without the recursive substitutions or their result proof.

A narrower exception independently audits final executable bytes for
straight-line leaves that normalize exactly one value and cannot signal,
trap, allocate, poll, call back or observe dynamic state. The host binds
that result to the actual immutable code object in a private, bounded
runtime registry. Layout, slot hints and compiler metadata supply no
authority, even when canonical WasmGC layouts match. Lookup checks the
entry identity and arity. Eviction keeps ordinary execution available.
Saved/restored objects carry no transient permission. The entry checkpoint
and retained ancestor frames still apply.

*** Numeric, branch and storage specialization

Target FIXNUM spans signed i64. Integers can be immediate i31 objects,
boxed i64 values or bignums. A logical interval can justify bounded
arithmetic or scalar extraction, while unchecked i31 extraction requires
physical representation evidence. Checked integer workers preserve
overflow promotion, general numeric contagion and errors. Native arithmetic
chains can use raw SSA locals to avoid intermediate boxes. Fresh executable
range facts can justify checked-policy i32 or i64 lowering, with the
selected widths based on both operand and result bounds.

A checked argument snapshot can seed an executable fact at the actual
check. Admission discards tentative checks, facts and consumers together
when the plan fails. A live structured-loop comparison can read an i64
local initialized at its dominating argument check. Copy chains can share
that local, while the original checked object remains available to other
uses. Private raw cells need proofs for the initial value,
each write and every relevant use, and reads retain independent snapshots.
Speed-oriented policy can also select guarded arithmetic or tiered storage
for some private counters. The ordinary numeric path handles unsupported
representations and overflow. Floating-point flow remains conservative,
and broad REAL declarations establish no floating-point representation.

Single-use predicates can feed forward branches without boxing a boolean.
Potential errors and backedge polls retain their required order. Reuse and
motion require stable operands and nontrapping operations. Proven list
and vector operations share checked helpers or use an admitted unchecked
lowering. Shared list paths cover composite accessors and eligible MEMBER
and ASSOC searches with known comparison controls. These plans preserve
intermediate list checks, array backing bounds, displaced storage,
mutation, sharing and freshness. Fixed AREF reads and writes can access
owned rank-one fixnum backing after checking its live dimension, layout
and bounds after the operation-entry checkpoint. A direct canonical AREF
read can pass an existing raw i64 arithmetic result or cell snapshot to
the checked rank-one reader. It checks the full subscript before narrowing
and resolves displaced storage through the ordinary live backing path.
The raw entry validates external references and checks physical backing
extents when that path follows a displaced view.
General dispatch and rank or bounds errors reconstruct the original index.
An untyped loop can use the same reader with an immediate index when its
private counter starts at zero, advances by one at its only write, and
continues strictly below an invariant bound. The bound can be a saved result
of an earlier computation such as LENGTH. A total representation test at
loop entry admits an i31 bound. Each continued iteration takes a scalar
snapshot at the comparison and reuses it for the successor and each
eligible AREF at their original instruction positions. These operations
keep their entry checkpoints, and each read resolves the current array
backing after its checkpoint. A bound outside the immediate representation
keeps the ordinary comparison, successor and read. Out-of-line NOTINLINE
calls and other boxed consumers keep their ordinary calling convention.
The runtime LOOP ACROSS expander validates the vector and captures its
active length during initialization, then reads current elements through
checked AREF.
General mutable list traversal supplies no list-length inference.

*** Scheduler work in native code

Interpreted evaluation, native function entries and loop checkpoints share
the running thread's work allowance. The core checks scheduler activity,
interrupt masking and synchronous host callback depth before charging work.
A pending Lisp interrupt and an exhausted allowance independently enter the
shared service. The service delivers queued work in the ordinary order,
preserves ambient result values and checks the monotonic deadline when the
allowance is exhausted. The nominal 4 ms slice uses the existing host
suspension and thread-switching paths when it expires.

Generated modules query a bounded allowance and report completed work through
checked function imports. The query reads the current allowance and pending
state without servicing either. A grant reserves no shared state. The runtime
debits completed units and owns all interrupt delivery, refill and suspension.
Both imports validate their raw counts. A caller must establish that its
chunk can run without an intervening required observation, then recheck
mutable facts after any service that can change them.

The bounded internal list comparison charges matched pairs. It keeps checked
cons access and reuses the advanced cursors across handoffs, checking each
next cell before use. Pending work keeps an ordinary backedge observation.
Early exits report the completed pairs and retain the original error order.

** Low-level Wasm optimization

*** Function body passes

Lowering uses forward structured control for acyclic regions and Wasm
loops for proved reducible natural loops. Irreducible control, captured
landings and exhausted analysis retain dense dispatch. Block arguments,
environments and backedge checkpoints survive either lowering.

Native compilation can batch checkpoints in a structured loop at the default
optimization levels. Maximum SPACE or SPEED 0 retains ordinary checkpoints.
The compiler audits the emitted Wasm after arity adaptation and local
optimization, so admission is independent of source syntax. A scheduler grant
bounds the work in each strip. The trip count can be unknown and the loop
can have dynamic exits or run indefinitely.

The audit requires a common latch and a fixed number of polls on every path
that reaches it. It accepts total scalar instructions, private local
operations and poll-free forward control flow. The ordinary and admitted
paths share the body. On a latch or a void exit, the emitter settles the exact
work performed, including the polls already traversed on a partially completed
trip. A denied or short grant keeps the ordinary checkpoints. Typed exit
payloads, unknown calls and mutable storage accesses retain ordinary lowering.

Structured native loops that keep ordinary polls can use epoch polling at
their existing poll sites. Each invocation holds a token combining the
scheduler epoch and prepaid work credit. A matching token with credit pays
for the observation inline. The slow path performs the ordinary checkpoint
and reserves bounded credit from the live budget after any service. The
scheduler advances the epoch on interrupt enqueue to the running thread,
segment and external callback entry, and budget refill. Credit expires on
an epoch change, and the runtime retains one unit for the service boundary.

The source evaluator and HIR interpreter share a private runtime token at
their existing evaluation and periodic instruction checkpoints. Native
modules encode immutable poll globals that support ordinary checkpointing.
The browser installer validates the final module before binding live globals
and checks that the module cannot write or re-export them. The loader
reestablishes read access when restoring code. Wasmtime binds the ordinary
constants and checkpoint helper.

=wasm-optimizer.lisp= runs a shared body pipeline over decoded Wasm.
Its principal transformations are:

- Fold local instruction patterns and constants. =native-clean-scopes=
  simplifies redundant scopes while preserving branch targets and signatures.
- =native-forward-locals= forwards compatible copies inside straight-line
  regions. Exception-aware liveness guides dead stores and typed local
  coalescing.
- =native-result-blocks= replaces eligible local joins with typed Wasm
  block results. Stackification is also subject to exception and control
  boundaries.
- Reencode changed locals, branch depths and relocations in the final
  function body.

=native-optimize-body= serves emitted code, typed workers and the linked
image optimizer. Shared native kernels and portable implementations
support the same logical passes. =optimize-wasm-module= applies these
passes before component packaging, keeps only smaller encodings, and
leaves unsupported bodies intact. It preserves the module ABI.

Compiler guests use the runtime liveness and instruction simplification
kernels directly, with scope cleanup and opcode filtering in the shared
Lisp pipeline. The host retains portable implementations of those passes.
The guest decoder and stackifier keep portable paths for cases outside
the native kernels' supported inputs.

*** Module passes

Module processing pools literals, merges equal code bodies, removes
unreachable functions and imports, and relocates references. It can fuse
common literal/lookup sequences and choose compact factory/table
representations based on encoded costs. Equal bodies can share code
without merging observable function or literal identities.

When packaging the browser image with the precompiled compiler, the host
lays out live function definitions to fit the most referenced functions
into one-byte Wasm indices. The WAT reachability pass counts symbolic
calls, tail calls and function references from retained definitions and
module fields. The layout retains the positions of anonymous and inline
export definitions and the order of table entries. Modules with imports
or numeric type operands keep the ordinary layout. Numeric function
references also prevent pruning.

=native-outline-code= moves repeated straight-line regions to typed helpers after
matching their normalized instructions, local aliases and signatures.
Live-ins become arguments and written locals are returned, including
writes observed through backedges. Regions cannot cross transfers or
consume an inherited operand stack. Bounded discovery considers multiple
region lengths and chooses nonoverlapping sites only when helper, call,
argument/result and section costs fit size policy. Exact comparison
establishes matches. Unknown types, unsupported control and exhausted
work leave ordinary code.

The host uses a lower minimum saving per helper and a larger helper
limit when outlining the final import-free image with the precompiled
compiler. Discovery retains its work bounds and caller policies. A second pass
in that image shares adjacent direct calls to two runtime transport
entries when the first result exactly matches the last parameter of the
second call. The first body must be short, straight-line and read-only,
including its direct callees. The private helper copies the first body
and tail-calls the second entry with the original operands, preserving
traps, live effects and handler continuations. Explicit caller policies
and helper costs limit site selection. The host validates the finished
Wasm module before packaging. The Node core embedded in the WASI REPL uses
the same image.

For the stripped precompiled image, the host tries one more local
optimization pass on the outlined code. It accepts that pass when the
final compact module validates and shrinks.
The compact layout assigns short function indices to frequently called
appended helpers. It swaps private function bodies and their type entries
and relocates direct calls and tail calls. Exports, table entries, and
targets of function references retain the indices used by snapshot
restoration.
The same compact pass combines an adjacent local null test, branch, and
reread into a null branch that carries the reference on fallthrough.
The branch depth and local assignment are preserved.
The host validates fallthrough simplifications with the original scopes
in place. It then removes unused void wrappers and merges adjacent
blocks with matching signatures, adjusting branch and catch depths.
Each stage keeps the previous bytes when validation rejects its candidate.

** Runtime optimization and extensions

*** Shared kernels and dispatch

Sealed Common Lisp kernels implement portable runtime algorithms above
the Wasm representation and platform substrate. The host linker checks
signatures, dependencies, captures and ownership. Public callers validate
inputs before unchecked traversal. Fixed callback linkage requires a
privately established identity and preserves callback effects. Host kernel
caching tracks live backend definitions so changes to passes reach
recompiled kernels.
Linked scalar integer extraction shares its null check at the private
helper entry before dispatching on the WasmGC integer representation.
Byte-field extraction checks the integer representations and count bounds
before extracting fields of up to 63 bits from a scalar integer. The
bounded path preserves sign extension and serves LDB and LDB-TEST under
the ordinary call checkpoint. MASK-FIELD shifts the extracted bits back
to their original position. Arbitrary-precision operands and wider fields
use the exact Common Lisp kernel.

Fixed native calls to BYTE, LDB, LDB-TEST and MASK-FIELD pass both
operands directly to the workers used by general application. The runtime
keeps the call and application checkpoints, authenticates the captured
builtin after both, and uses the ordinary backtrace frame and dynamic
cleanup even when the worker signals. Debugger evaluation and dispatch
misses follow general application. MASK-FIELD rereads the bytespec
position after extraction.

Fixed native calls with two or three operands to LOGAND, LOGIOR, LOGXOR
and LOGEQV share a scalar fold. After the call checkpoint, the runtime
checks the captured builtin against its canonical identity and accepts
immediate signed i31 and boxed signed i64 operands. The fold uses signed
64-bit words and normalizes one result. General application handles
debugger evaluation, arbitrary-precision operands and type errors.

Generic dispatch caches method selection under runtime ownership, with
checks on the actual discriminator, type and method state, argument
classes and specializers, adapter and native entry. Current property
values still come from live binding cells. A callback or poll ends any
assumed selection interval. Commit paths reread the relevant owners and
versions before entry, and a miss returns to live dispatch, including a
replacement discriminator. Native methods and generated effective methods
retain method combination, auxiliary methods and escaped CALL-NEXT-METHOD
context. Method specializers supply no unchecked method-body type
declaration. The narrow fixed selector leaves one worker slot for
hidden context. Wider calls retain packet dispatch.

Owned metadata can cache normalized method keyword lists and validated
generic property-spine shape. Queries preserve live METHOD-LAMBDA-LIST
and other MOP callbacks, return independent keyword spines, and recheck
ownership before consuming descriptors. Mutation, borrowing and
replacement can revoke ownership. Restored descriptors must reestablish
transient proofs. A bounded private constructor plan covers simple
finalized standard classes with canonical initialization methods and
matching initargs. Each hit rechecks method, class and protocol identities
and allocates fresh instance storage. Custom methods, defaults and more
general layouts use ordinary construction.

*** Extension boundaries

- Package-local nickname declarations and the private package bridge
  share one checked registry. Updates validate before publication, and
  deletion clears both owned and targeting aliases. Readable printing
  must choose a prefix that resolves to the actual package. The optional
  MIRICL-PACKAGES and UIOP facades use the same underlying identities.
- The optional Gray stream protocol extends the canonical stream classes
  and applicable generic functions. Logical membership supplies no native
  storage proof. The runtime checks callback results, direction, open
  state and sequence bounds, including bounds that a callback can change.
  Per-stream pending input survives recursive switches. Reader macros and
  user printers receive their actual protocol stream.
- The optional IDE MOP service provides shared slot-documentation
  functions using canonical identities and validates capabilities before
  replacing placeholders. The IDE session service validates requests and
  executes them serially in the guest, preserving the session's package,
  readtable, complete result groups and ordered output. Compilation uses
  COMPILE-FILE and LOAD over private scratch files. Interactive input,
  debugger UI and original-file compilation in the initial LEM provider
  remain unavailable.

*** Images and host adapters

Public compiler, cold and compiler-free images contain a gzip-compressed
matching adapter in one =miricl.adapter.gz= custom section. =loadMiricl=
from =miricl-loader.mjs= accepts image bytes and host source types, handles
outer download compression, and instantiates with the embedded adapter.
=getMiriclAdapter= exposes the checked bytes and adapter module.
=Miricl.instantiate= leaves adapter loading explicit. Saved images retain
the same adapter. The WASI terminal component provides its executable relay
to Wasmtime and carries the Node compiler image and relay core in separate
top-level custom sections. The Node launcher validates the enclosing section
bounds and extracts the core for the selected operation. The complete default
browser image has a 1 MiB raw budget, including its adapter.

Saved images retain reachable state, native code and captures. The loader
validates field layouts, reference bounds and graphs against exported
runtime descriptors. It reconstructs immutable references before dependent
objects and fills mutable references while preserving cycles and sharing.
Transient scheduler, decoder and executable-permission state is rebuilt
or falls back after restoration.

Application build caches bind actual mounted inputs, pins, generated data,
tools and matching runtime/compiler artifacts. A reused artifact still
receives source authentication and restore checks. The LEM builder loads
its selected ASDF graph inside Wasm and saves the guest before editor UI
startup. Existing portable FASLs are independent of whether application
functions have native entries.

** Implementation limits

General native binders can still copy argument transport across the call
boundary. Keyword lookup can repeat scans when a binder needs both presence
and value. DYNAMIC-EXTENT declarations do not currently support continuation
scalarization. Known standard identities can have incomplete effect facts or
only the general lowering.
