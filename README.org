** Q&A

*** What is miricl?

Currently it's a Common Lisp interpreter for Wasm runtimes (such as
browsers, Node.js and Wasmtime). You can try it in your browser [[https://ak-coram.github.io/miricl/][here]].

*** Is it slop?

Absolutely! I didn't even read most of the source.

*** Why?

As usual this project intends to fill a void: the current interpreter
is a [[https://ak-coram.github.io/miricl/image-sizes.html][fraction of the size]] of ECL compiled with Emscripten to
Wasm. This enables deployment of Common Lisp programs in environments
where size can be an issue (such as [[https://ak-coram.github.io/miricl/todo.html][websites]]).

*** How?

I've set up a cage fighting match between an LLM and [[https://gitlab.common-lisp.net/ansi-test/ansi-test][ansi-test]] which
lasted for days. You can view the results [[https://ak-coram.github.io/miricl/ansi-results.html][here]].

Run the full interpreter suite with =just full-ansi=.
The native compiler has a separate ANSI mode: =just ansi-compiler=, or
=just full-ansi-compiler= for the full upstream suite. The runner first triggers
compiler self-compilation and verifies the native frontend and backend. Setup and helper
definitions currently use the interpreter; test bodies run as native Wasm.
Unsupported compilation counts as failure, with no interpreted fallback.
Results go to =ansi-compiler-results.json=, including bootstrap details and per-test compilation counts.

*** Don't you care how the sausage is made?

I prefer an unethical sausage to no sausage.

*** Are you asking for funding?

Yes, tokens don't grow on trees and that's what I spend any funding
on.

** Usage

*** Distribution

The =miricl-runtime= build artifact contains four files:

- =miricl.js=: browser adapter and Node terminal command.
- =miricl.wasm=: interpreter and compiler for browsers and Node.
- =miricl-repl.wasm=: Wasmtime terminal command and precompiled compiler for Node.
- =miricl-asdf.wasm=: optional ASDF/UIOP library.

Keep these files together. Node and Wasmtime commands below work without a
MIRICL checkout; browser applications import =miricl.js= directly. ASDF is needed
for development and bundling, but ordinary production applications only need
the adapter, interpreter and their application FASL.

*** Building from source

**** Prerequisites

- A host Common Lisp implementation and Quicklisp. The commands below use
  SBCL and expect Quicklisp at =~/quicklisp/setup.lisp=.
- The [[https://github.com/bytecodealliance/wasmtime/releases/][Wasmtime C API shared library]], version 50 (CI uses 50.0.1).
  Install the C API library separately from the Wasmtime CLI. Make
  =libwasmtime.so=, =libwasmtime.dylib= or =wasmtime.dll= discoverable by
  your system's library loader; use =LD_LIBRARY_PATH= on Linux,
  =DYLD_LIBRARY_PATH= on macOS or =PATH= on Windows for a custom location.
- Git and [[https://just.systems/][just]] for the checkout and build commands.
- Node.js 26 (used by CI) for the Node REPL and size reports.
- The Wasmtime 50 CLI and =rlwrap= for the terminal examples below.
- A browser supporting WasmGC and Wasm exception handling
  for the small HTML example.

**** Build

Run the following from a terminal:

#+begin_src sh
git clone https://github.com/ak-coram/miricl.git
cd miricl
just build-asdf
#+end_src

This produces =miricl.wasm=, the import-free interpreter, and
=miricl-repl.wasm=, the WASI 0.3 terminal REPL and development command. Both include the
REPL bridge and the compiler. It also writes =miricl.js= and the optional =miricl-asdf.wasm=.
Quicklisp loads the Lisp dependencies automatically. If your Quicklisp
setup file is elsewhere, set =QUICKLISP_SETUP= when building:

#+begin_src sh
QUICKLISP_SETUP=/path/to/quicklisp/setup.lisp just build
#+end_src

*** Terminal REPL

Start a local terminal REPL with either command:

#+begin_src sh
node miricl.js miricl.wasm
wasmtime run -W stack-switching=y -S p3=y miricl-repl.wasm
#+end_src

These commands evaluate locally and open no network listeners.

*** A small HTML page

Save this as =hello.html= beside the distribution files:

#+begin_src html
<!doctype html>
<meta charset="utf-8">
<title>Common Lisp hello world</title>

<script type="text/x-common-lisp">
  (js:invoke (js:global "console") "log" "Hello, world from Common Lisp!")
</script>

<script type="module">
  import {Miricl} from "./miricl.js";

  const bytes = await (await fetch("./miricl.wasm")).arrayBuffer();
  const lisp = await Miricl.instantiate(bytes);
  for (const script of document.querySelectorAll('script[type="text/x-common-lisp"]')) {
    lisp.evaluate(script.textContent, {eof: true});
  }
</script>
#+end_src

The adapter enables JS interop automatically. The loop evaluates every
=text/x-common-lisp= script in document order, sharing one
interpreter, so later scripts can use definitions from earlier ones.

Serve the current directory so the browser can load the JavaScript
module and Wasm file:

#+begin_src sh
node miricl.js miricl.wasm --dev-server
#+end_src

Open [[http://127.0.0.1:8000/hello.html][hello.html]] and check the browser's developer console for =Hello,
world from Common Lisp!=. This calls the browser's =console.log= from
Common Lisp via =js:invoke=.

*** Development mode

Save this as =dev.html= beside the distribution files:

#+begin_src html
<!doctype html>
<meta charset="utf-8">
<title>Common Lisp development</title>
<script type="module">
  import {Miricl} from "./miricl.js";

  const bytes = await (await fetch("./miricl.wasm")).arrayBuffer();
  const lisp = await Miricl.instantiate(bytes, {dev: true});
</script>
#+end_src

Start the terminal browser REPL and serve the current directory with
either Node or Wasmtime. These commands enable HTTP and WebSocket;
the TCP REPL listener is disabled unless =--repl-bridge= is also supplied:

#+begin_src sh
node miricl.js miricl.wasm --dev-server

wasmtime run -W stack-switching=y -S p3=y -S inherit-network=y \
  --dir .::. miricl-repl.wasm --dev-server
#+end_src

Open [[http://127.0.0.1:8000/dev.html][dev.html]], then evaluate this in the terminal to show a browser alert:

#+begin_src lisp
(js:invoke (js:global "window") "alert" "Hello, world!")
#+end_src

Evaluations run in the browser application's interpreter; connection
status appears in the terminal. Use =--browser-repl= instead of
=--dev-server= if files are served elsewhere.
Omit =dev= in production to disable the adapter and connection.
Enter =:quit= to stop the host command and detach the development adapter.

Development mode reads host files through the dev server automatically. The
served directory appears as =/= to Lisp; =load=, =open=, =directory= and file
timestamps work through =evaluateAsync= and the terminal REPL. Writes and compiled
files stay in the browser. Use ={dev: {filesystem: false}}= to disable file access,
or set =filesystem= to the dev server's HTTP URL when serving the webapp elsewhere.

Ports default to HTTP 8000, WebSocket 4006 and TCP 4005 (when enabled); override them
with =--http-port=, =--websocket-port= and =--tcp-port=. For a custom
WebSocket port, use ={dev: {url: "ws://127.0.0.1:PORT/repl"}}=.

**** Emacs

Add =--repl-bridge= to either command to enable the TCP REPL on
=127.0.0.1:4005=. Evaluate this in your Lisp source buffer to connect
directly, keeping the REPL selection buffer-local:

#+begin_src emacs-lisp
(progn
  (require 'inf-lisp)
  (setq-local inferior-lisp-buffer "*miricl*")
  (pop-to-buffer (make-comint "miricl" '("127.0.0.1" . 4005)))
  (inferior-lisp-mode))
#+end_src

This provides an inferior Lisp buffer and source evaluation commands.
The buffer shows browser connection status and stays connected across
browser reloads. TCP submissions and responses also appear in the
terminal. Interrupts and Swank/Slynk are not implemented.

*** ASDF

Build the optional ASDF/UIOP library from the pinned upstream Git submodule:

#+begin_src sh
just asdf-init
just build-asdf
#+end_src

This applies =patches/asdf/series= to a source copy under =build/asdf/source/=
and compiles it to =miricl-asdf.wasm=. The submodule stays clean; a failed patch
stops the build. The distribution already includes this optional file; ASDF is
not included in the base interpreter images.

With the application directory served by the dev server and ={dev: true}= in the browser,
load ASDF and your application's system from the terminal:

#+begin_src lisp
(load "/miricl-asdf.wasm")
(asdf:load-asd #P"/app/app.asd")
(asdf:load-system "app")
#+end_src

Use =asdf:initialize-source-registry= to discover systems under a directory.
Host source edits are visible on subsequent loads; compiled =.wasm= FASLs stay
in memory and can be loaded in another interpreter without ASDF. Outside dev
mode, supply files explicitly with =mountFile=. Run =just test-asdf= to check
the port and =just test-browser-dev= for browser access through both servers.

**** Production bundles

Select ASDF's monolithic bundle operation to include the system and its
dependencies in one loadable file:

#+begin_src lisp
(asdf:defsystem "app"
  :depends-on ("some-library")
  :serial t
  :components ((:file "package") (:file "app"))
  :build-operation "monolithic-compile-bundle-op"
  :build-pathname #P"dist/app.wasm")

(asdf:make "app")
#+end_src

The shipped terminal REPLs can build the system without a browser:

#+begin_src sh
node miricl.js miricl.wasm --bundle app --output dist/app.wasm
wasmtime run -W stack-switching=y -S p3=y --dir . miricl-repl.wasm --bundle app --output dist/app.wasm
#+end_src

Place =miricl-asdf.wasm= beside the application (or in =runtime/=) and optionally
provide =systems.lisp= to configure its source registry and output translations.
Wasmtime also needs named preopens for directory symlinks outside the root.
Builds use a fresh interpreter, write the requested FASL, then exit. No entry
point is called, and no adapter, interpreter or other assets are copied.
ASDF may load earlier components while compiling later ones; keep browser
side effects in startup code or use =eval-when= to control evaluation.

The same Lisp operation is available in a terminal REPL:

#+begin_src lisp
(miricl-bundle:dump-system "app" :output "dist/app.wasm")
#+end_src

With =:save nil=, the bundle remains in the interpreter's virtual filesystem;
=await lisp.readFile("/dist/app.wasm")= retrieves its bytes. The adapter and interpreter are separate distribution files that can be referenced or symlinked into applications.

In production, mount and load only the bundle, then start the application:

#+begin_src javascript
const lisp = await Miricl.instantiate(interpreterBytes);
lisp.mountFile("/app.wasm", await (await fetch("./app.wasm")).arrayBuffer());
await lisp.evaluateAsync('(load "/app.wasm") (app:start)', {eof: true});
#+end_src

ASDF and source files are not needed at runtime unless the application itself
uses them. If needed, mount and load =miricl-asdf.wasm= explicitly before the
application bundle. Bundling does not add ASDF/UIOP automatically. Bundles retain
interpreter code and load-time initialization;
they are not standalone executables or whole-program optimized Wasm.
Declare and supply non-Lisp resources separately. =compile-bundle-op= bundles
only one system; =monolithic-compile-bundle-op= includes its dependencies.

**** Compiler

The compiler is built into both images and shares the interpreter's Lisp objects:

#+begin_src javascript
const lisp = await Miricl.instantiate(interpreterBytes);
lisp.evaluate("(defparameter *f* (miricl-compiler:compile-native '(lambda (x) (+ x 2))))");
lisp.evaluate('(funcall *f* 40)'); // 42
#+end_src

The browser image carries compact compiler source; the first compilation
self-compiles the frontend and emitter once and reuses their native functions.
The REPL deliverable includes the self-compiled compiler for Node and Wasmtime.
Development REPL expressions and =defun= bodies compile on that host and execute
in the browser, preserving its macros, objects and REPL history. Forms that establish
packages, macros, classes and methods still use the browser evaluator.
The native
backend currently supports a subset of Common Lisp. Browser and Node adapters
can instantiate generated Wasm; the WASI compiler can emit and optimize files.
ASDF remains a separate, explicitly loaded library.

**** Whole-program optimization

The initial compiler backend removes unreachable definitions and constants
while still emitting an interpreted FASL. Specify the production entry points:

#+begin_src sh
node miricl.js --optimize app --entry APP:START --output dist/app.wasm --report dist/retention.txt
wasmtime run -W stack-switching=y -S p3=y --dir . miricl-repl.wasm --optimize app --entry APP:START --output dist/app.wasm
#+end_src

Repeat =--entry= for other public functions and =--keep PACKAGE:NAME= for
definitions accessed dynamically. JavaScript callbacks referenced by Lisp are
retained automatically. Package exports alone do not retain definitions.
Initialization effects and potentially applicable methods are preserved;
unbounded reflective lookup conservatively retains the supplied program.
The report explains each retained or removed definition. FASL units without
compiler metadata prevent pruning. No entry point is invoked by the optimizer.

Pass =--no-strip= with =--optimize= to retain all definitions while compacting
the FASL. Entry points are optional in this mode:

#+begin_src sh
node miricl.js --optimize app --no-strip --output dist/app.wasm
wasmtime run -W stack-switching=y -S p3=y --dir . miricl-repl.wasm --optimize app --no-strip --output dist/app.wasm
#+end_src

The corresponding Lisp API is =miricl-compiler:optimize-system= with
=:entry-points=, =:keep=, =:output=, =:report= and =:save= options. Use =:strip nil=
to disable definition stripping.
=miricl-compiler:shake-file= operates on an existing bundle without executing it
and is also available to the host Common Lisp system. See [[./compiler.org][compiler architecture]].

*** Game of Life

The [[./game-of-life/README.org][Game of Life example]] uses the FSet 2 API, an ASDF application bundle,
and a browser/terminal development REPL. Run =just setup-game-of-life=, then
=cd game-of-life && just dev=. Both development and production builds use
the WASI REPL with its precompiled compiler. =just build= writes =build/index.html=,
=miricl.js=, =miricl.wasm= and =game-of-life.wasm= as separate files.
[[https://ak-coram.github.io/miricl/game-of-life/][Play the production build]].
Run =just benchmark-game-of-life= from the repository root to measure production
sizes and fresh application loading;
results are in =game-of-life/build/sizes.json=.
