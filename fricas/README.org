* FriCAS on MIRICL

[[https://github.com/fricas/fricas][Canonical FriCAS]] is pinned in =vendor/fricas=. The [[https://ak-coram.github.io/miricl/fricas/][browser workbench]]
uses MIRICL for parsing, type inference, algebra and compilation. Calculations
run locally in a worker. The Plan 9 interface shares Maxima's recording,
export, replay and cancellation controls; saved sessions use a separate key.

** Build and run

Install SBCL, GNU make and a C compiler, plus the usual MIRICL prerequisites.
Then run from the repository root:

#+begin_src sh
just build-fricas
node scripts/repl.mjs miricl.wasm --dev-server --directory=build/fricas/site
just test-fricas
#+end_src

MIRICL build stages and the browser distribution use =miricl.wasm=,
with its bootstrapped native compiler ready at startup. This avoids repeating
compiler bootstrapping when the build creates a fresh interpreter. The static
site keeps the runtime filename =miricl.wasm=.

The native FriCAS build is only a bootstrap: upstream =configure=, =make= and
=make dist-lisp= generate portable Common Lisp and four algebra databases.
MIRICL compiles the interpreter into =build/fricas/fricas.wasm=. The generic
optimizer preserves its dynamic interface and compiles its retained functions
and initializers to WASM. All 1,423 portable algebra libraries are compiled
during packaging, compacted with =shake-file :strip nil=, compiled to native
WASM functions with =compile-native-bundle=, and loaded on demand
from the guest filesystem. Compaction retains every algebra definition. First use
therefore loads compiled libraries without compiling their source.
The browser ships compiled algebra, command help and databases in
=filesystem.bin.gz=. Algebra source files, SBCL and native FriCAS are not needed
by the browser. Build artifacts are cached under a fingerprint of the runtime,
core and algebra sources; interrupted builds cannot reuse partial files.

=build/fricas/site= is the static distribution. =build.json= records the
upstream revision and image hashes; =optimization.json= and =retention.txt=
record optimizer measurements. The size page counts the entire initial
application, including the compressed algebra filesystem.

** Examples and tests

The shelf examples come from the pinned upstream HyperDoc source: symbolic
integration with a real parameter, differentiation, lazy power series,
series arithmetic, limits and block matrices. Each links to its source.
Command help, for example =)help clear=, is available offline.

=tests/fricas.mjs= checks the optimized image, examples, session state, and
complete upstream =array.input=, =table.input= and =ord.input= suites. The
browser test checks offline evaluation, Unicode, recording, saved transcripts,
replay, mobile layout and cancellation. These run in the regular Linux/SBCL
CI job. Pages only builds and publishes. They are selected regression coverage,
not a claim that the entire upstream FriCAS test suite passes.

Native socket, shell, X/HyperDoc and graphics front ends are not part of this
browser port. The included algebra and text interface do not require them.
